registry ​

Manage the asset registry for tracking current assets per zone.

What it does ​

The registry command manages the Asset Registry, which tracks the current asset ID for each zone. This enables:

  • NO_CHANGE action to reuse existing assets
  • Asset ID continuity across refreshes
  • Tracking what's currently live

When to use it ​

  • Viewing current asset assignments
  • Rebuilding registry after manual changes
  • Clearing registry to start fresh

Usage ​

bash
# Show registry (default view)
make registry

# Bootstrap from existing files
make registry ARGS="--bootstrap"

# Clear registry
make registry ARGS="--clear"

# List all IPIDs in the registry
make registry ARGS="--ipids"

How Registry Affects Processing ​

ActionRegistry Behavior
LAUNCHCreates new entry with new asset ID
UPDATEUses existing asset ID from registry
REMOVERemoves entry from registry
NO_CHANGEReads asset ID from registry (no processing)

How IPIDs are built ​

IPID = tracking ID used in links (e.g. for analytics). The registry stores one ipid per zone item; make registry ARGS="--ipids" lists them all.

Canonical format ​

IPIDs follow a single structure (underscore-separated, lowercase):

{brand}_{page}_{device}_{zone}_{position}_{promo}_{destination}_{date}
1
SegmentSourceExample
brandBrand IPID segment (loft or at from BRANDS_CONFIG)loft
pageAsset type → page (HOMEPAGE→hp, PPH→pph, POPUP→popup, etc.)hp
deviceItem device or allall
zoneZone key, slugifiedhp-2t, pph
position1-based index in zone1, 2
promoCopy/copyMessage, slugified (or np)60offmusthaves, np
destinationdestination.type + destination.id slugified, or nacategorycatl00009, na
dateRefresh date in MMDDYY021126

Example: loft_hp_all_pph_1_60offmusthaves_categorycat5490004_021126.

Where they’re built ​

  • When: During refresh/slot processing in ExcelWorkflow when building zone items for LAUNCH or UPDATE (non-reused). For NO_CHANGE or reused UPDATE, IPIDs come from the existing registry entry.
  • Code: ExcelWorkflow._buildIpidForItem() builds each item’s IPID and calls buildIpid() in src/utils/helpers with brand, page, device, zone, position, promo, destination, and refresh date. Promo and destination are passed through slugifyCompact() (alphanumeric only, max 30 chars); date is formatted with formatDateMMDDYY() (MMDDYY).
  • Registry: When a zone is registered (e.g. on sync), the same items (with their ipid fields) are stored in the registry. make registry-ipids reads registry.getAllItems(), filters to items that have an ipid, and prints asset type, zone, order, and IPID.

So IPIDs are built once when the refresh is processed (from wireframe data + refresh date + brand); they are then stored in zone data and in the registry, and listed by make registry ARGS="--ipids".

Make equivalents ​

bash
make registry                    # Show registry (zones + item counts)
make registry ARGS="--ipids"     # List all IPIDs (asset type, zone, order, IPID)

2

Where registry lives

The registry is stored in dev-env: dev-env/{brand}/asset-registry.json. If you delete or reset dev-env, the registry is lost. Run make registry ARGS="--bootstrap" to repopulate it from existing refresh folders (local data only; this does not read from SFCC).

Make commands

Use make registry for default view, make registry ARGS="--ipids" for IPID list. Advanced operations: make registry ARGS="--bootstrap" or ARGS="--clear".
