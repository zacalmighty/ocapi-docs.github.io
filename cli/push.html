push ​

Validate data quality, validate payload structure, then sync to SFCC staging.

Once a refresh is synced, running make push again for that same refresh is blocked unless:

  • The refresh is stale (new data arrived via make pull since last sync) — push proceeds automatically
  • You pass FORCE=1 for manual overrides (e.g., template-only changes)

Use the normal next steps (replicate, done, commit) instead of re-pushing.

Usage ​

bash
make push                        # Uses sticky date
make push DATE=2026-02-14        # Override for one command
make push DATE=2026-02-14 REFRESH=r2
make push DATE=2026-02-14 ALL=1  # Sync every refresh in the date
make push DATE=2026-02-14 FORCE=1  # Re-push an already-synced refresh (e.g. after SFCC changes)

  3. explicit error in non-interactive mode (provide REFRESH or ALL=1)

What It Does ​

The push command runs a three-stage validation pipeline before syncing:

Stage 1: Data Quality Checks ​

Extracted from the validate command, these checks run automatically:

Missing destination ID on HOMEPAGE itemsError
Missing IPID on HOMEPAGE itemsWarning
Duplicate IPIDsWarning
Unknown asset types (not in configured asset types)Warning

     • 3 items missing copy (LAUNCH)
     • 1 missing destination ID (HOMEPAGE)

  Fix the issues in the Excel and re-fetch with make pull.

Stage 2: Payload Structure Validation ​

Checks the OCAPI payload for structural integrity:

  • Campaign metadata present and valid
  • All assets have required fields (id, name, c_body)
  • Slot configurations reference valid assets
  • Slot bindings are complete

Stage 3: OCAPI Sync ​

Validation Pipeline ​

Sync state and config (single file) ​

On success, the command writes status and last-synced config into sync-config.json (one file):

  • Status fields: synced, stale, staleReason, staleSince, lastSyncedAt, lastAttemptAt, error, campaignId, refreshPath
  • Config: campaign_id, name, slots (with asset content), etc., for sync diff and upload-by-prefix

So sync-status.json and sync config are combined in sync-config.json. The file is tracked in Git and activates the build guard for other producers.

Already synced / No changes ​

If the refresh has already been synced (sync-config.json has synced: true), push exits without calling OCAPI:

text
  • 📅 Found refresh for 2026-02-10/r1: dev-env/loft/refreshes/2026-02-10/r1/refresh.json
  • Already synced: 2026-02-10/r1. Use `make push FORCE=1` to re-push.
1
2

Stale refresh (changeout after sync) ​

If make pull brought new data for an already-synced refresh, the system marks it stale and push proceeds automatically:

text
  • 🔄 Re-syncing 2026-02-10/r1 — source data changed since last push.
  • 📦 Syncing loft / 2026-02-10 / r1
  • ✅ Synced 2026-02-10/r1: 3 created, 6 updated
1
2
3

After a successful push the stale flag is cleared. No FORCE=1 needed.

Force re-push ​

When you re-push with FORCE=1 and SFCC already has the same content (no asset or slot changes), the command skips slot binding and reports:

text
  • SFCC already has this date; no changes to sync for 2026-02-10/r1.
1

Only when something actually changed will you see Synced …: X created, Y updated. The email is auto-generated and copied to clipboard. Use make replicate for replication steps, then make commit to save. Use make push FORCE=1 only when you need to re-push (e.g. after fixing something in SFCC or after a forced rebuild).

Options ​

Flag / Make varDescription
--dry-runShow what would sync without making changes
--yes / -ySkip warning confirmation prompt
FORCE=1 / --forceAllow re-push when refresh is already synced
--skip-assetsSync only slots (not assets)
--skip-slotsSync only assets (not slots)

Retry Behavior ​

Retry logic is handled entirely by ApiClient (OCAPI_RUNTIME.maxRetries with exponential backoff and Retry-After header support). The SyncToSfcc use case does not add its own retry layer, avoiding stacked retries.

Prerequisites ​

  • OCAPI must be enabled: run make setup and enable OCAPI
  • Date must be built first: make build
  • SFCC credentials configured: make health to verify

If OCAPI is disabled, push exits early before validation/sync:

text
  • 📅 Found refresh for 2026-02-10/r1: dev-env/loft/refreshes/2026-02-10/r1/refresh.json
  ⚠ ⚠️  OCAPI not enabled. Run 'make setup' and enable OCAPI.
