refresh ​

The refresh CLI command forces a full rebuild of HTML and OCAPI payload. From the shell, use make build FORCE=1 to force-rebuild after template edits; it bypasses build guards.

make build vs make build FORCE=1

make build runs the guarded build, then watches templates/ and src/config (save = rebuild). make build FORCE=1 bypasses guards. See build.

What it does ​

The refresh command transforms Refresh DTOs into Campaign entities and generates all output files:

  • HTML assets rendered from Handlebars templates
  • JSON data files for each asset
  • OCAPI payload for sync to SFCC

Usage ​

bash
# Guarded build (skips if already built/synced)
make build                       # Uses sticky date
make build DATE=2026-02-03       # Specific date

# Force rebuild (bypasses guards)
make build FORCE=1               # Uses sticky date
make build DATE=2026-02-03 FORCE=1   # Specific date

Processing Flow ​

Build Guards ​

When called via make build (without --force), these guards apply:

StateBehavior
Already synced (sync-config.json with synced: true)Blocked — suggests make build FORCE=1 or make status to pick another refresh
Already built (ocapi-payload.json exists)Skipped — suggests make push or make build FORCE=1
New / UpdatedProceeds normally

make build FORCE=1 passes --force, bypassing these guards.

Error Handling ​

ErrorCauseSolution
"No refresh found"Missing refresh.jsonRun make pull first
"Template not found"Missing template fileCheck templates/ directory
"Validation failed"Invalid refresh dataCheck refresh.json structure
"Already synced"Build guard triggeredUse make build FORCE=1 to force, or make status to pick another refresh
