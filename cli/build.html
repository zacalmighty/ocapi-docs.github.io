build ​

Alias for make preview --no-zone-picker. Auto-builds if stale (shows diff + approval prompt), then generates composed preview output. No file browser is shown at the end.

Usage ​

bash
make build                       # Uses sticky date
make build DATE=2026-02-14       # Override for one command
make build DATE=2026-02-14 REFRESH=r2
make build DATE=2026-02-14 ALL=1 # Build all refreshes for date
1
2
3
4

If a date has multiple refreshes and REFRESH is omitted, build resolves in this order:

  1. sticky date/r# from .ocapi-config.json (brandState.{brand}.currentDate)
  2. interactive refresh picker (TTY)
  3. non-interactive prompt to pass explicit REFRESH (or ALL=1)

What It Does ​

  1. Loads refresh.json for the selected date
  2. Checks build guards (see below)
  3. If stale, shows diff and prompts for approval
  4. Compiles Refresh DTO into Campaign domain model
  5. Generates HTML from Handlebars templates
  6. Writes ocapi-payload.json (SFCC-ready)
  7. Shows file count and next step hint

Build Guards ​

Before generating, the build command checks the current state of the date to prevent accidental overwrites.

Already Synced ​

If sync-config.json shows synced: true:

  ⚠  Already synced. Choose a different refresh or rebuild:
     make status          (pick a different refresh)
     make build FORCE=1   (force rebuild)
1
2
3

Why: Another producer (or you) already pushed this date to SFCC. Rebuilding would overwrite their work.

Updated (stale — new data since last sync) ​

If sync-config.json shows synced: true and stale: true (set automatically when make pull brings changed data):

  📅 2026-02-08 (NFP 70 / FP 50%)

  🔄 New data detected since last sync
  [Shows diff of changes]

  Approve and rebuild
  Skip

7

Why: A changeout arrived. The system shows a diff and prompts for approval — this is an approval-based guard (not blocking). If approved, rebuild proceeds automatically — no FORCE=1 needed.

Already Built ​

If ocapi-payload.json exists:

  ✔  Already built.
     make push            (push as-is)
     make build FORCE=1   (rebuild)

Why: The HTML and payload are already generated. No need to regenerate unless templates changed.

Force Rebuild ​

Use make build FORCE=1 to bypass the build guard:

bash
make build FORCE=1               # Force-rebuild selected date
make build DATE=2026-02-14 FORCE=1   # Force-rebuild specific date
1
2

The FORCE=1 variable passes --force to the CLI, bypassing the build guard. This is intended for use after editing templates or config.

Refresh (low-level) ​

The refresh CLI command is the underlying build: it transforms Refresh DTOs into Campaign entities and generates HTML, JSON, and OCAPI payload. Producers use make build (which runs preview with --no-zone-picker and applies build guards). The refresh command is used internally by make status "Rebuild (force)" and by make build-all (one build per date). For force-rebuild from the shell use make build FORCE=1; it bypasses build guards. There is no separate per-command page for refresh.

Related ​

  • push — Sync the built date to SFCC
  • status — Pick another refresh (sets active) and run an action
  • preview — Review before pushing
