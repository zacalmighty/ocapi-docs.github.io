SFCC Import Feature (Future Implementation) ​

Status: Planned for Phase 2
Priority: Medium
Estimated Effort: 2-3 days

Overview ​

The Import feature will allow bootstrapping the application with historical campaign data directly from SFCC. This enables:

  1. Seamless transition - No "day 1 gap" when adopting the system
  2. Complete NO_CHANGE tracking - Registry knows what's already live
  3. Historical reference - Full audit trail from SFCC
  4. Rollback capability - Access to previous content states

Proposed Command ​

bash
make import                    # Import all campaigns
make import DATE=2025-06-15    # Import specific date
make import --dry-run          # Preview what would be imported

How It Works ​

Data Flow ​

SFCC (Production)
    │
    ├── Campaigns (with date ranges)
    │       ↓
    ├── Slot Configurations (assigned to campaigns)
    │       ↓
    └── Content Assets (HTML bodies)
            ↓
    ┌───────────────────────────────────────┐
    │  Import Process                        │
    │  1. Fetch campaigns via OCAPI          │
    │  2. Map slots to zone structure        │
    │  3. Extract content from assets        │
    │  4. Build refresh.json files           │
    │  5. Update asset registry              │
    └───────────────────────────────────────┘
            ↓
dev-env/{brand}/refreshes/{date}/r1/
    ├── refresh.json      ← Same format as Excel-parsed data
    ├── preview/
    │   ├── templates/    ← Original HTML from SFCC
    │   └── rendered/     ← Can regenerate if needed
    └── ocapi-payload.json

3. ImportFromSfcc Use Case ​

javascript
class ImportFromSfcc extends BaseUseCase {
  async execute(options = {}) {
    const { date, dryRun } = options;

    // 1. Fetch campaigns
    const campaigns = await this.ocapi.getCampaigns();

    // 2. Filter by date if specified
    const filtered = date ? campaigns.filter((c) => c.start_date === date) : campaigns;

    // 3. Process each campaign
    for (const campaign of filtered) {
      // Get slot configurations
      const slots = await this.ocapi.getSlotConfigs(campaign.id);

      // Build refresh structure
      const zones = {};
      for (const slot of slots) {
        const content = await this.ocapi.getContentAsset(slot.content_id);
        const mapping = this.mapper.mapSlotToZone(slot.slot_id);

        if (!zones[mapping.assetType]) {
          zones[mapping.assetType] = {
            assetType: mapping.assetType,
            items: [],
          };
        }

        zones[mapping.assetType].items.push({
          zone: mapping.zone,
          action: "LAUNCH",
          html: content.body,
          // Parse HTML to extract copy, destination, ipid if possible
          ...this.mapper.parseHtmlContent(content.body),
        });
      }

      // 4. Build refresh.json
      const refresh = {
        campaign: {
          brand: this.brand.name,
          campaign_id: `${this.brand.id}-${campaign.start_date}-r1`,
          name: campaign.name,
          start_date: campaign.start_date,
          end_date: campaign.end_date,
        },
        zones,
      };

      // 5. Save (unless dry run)
      if (!dryRun) {
        await this.fileStore.saveRefresh(refresh);
        await this.registry.registerFromRefresh(refresh, { source: "sfcc-import" });
      }
    }
  }
}

Rollback referencePrevious content available locally

Considerations ​

1. Large Data Volume ​

Ann Taylor has 280+ refreshes per year. Import should:

  • Support incremental imports (by date range)
  • Show progress indicators
  • Allow resumption if interrupted

2. HTML Parsing Limitations ​

Not all content can be reverse-parsed:

  • IPIDs may not be extractable from all HTML
  • Copy text may be embedded in complex markup
  • Destinations may use SFCC variables

Mitigation: Store raw HTML and mark as "imported" - full parsing optional.

3. One-Time vs Ongoing ​

  • Initial import: Full historical pull
  • Ongoing: Optional periodic sync to catch manual SFCC edits
