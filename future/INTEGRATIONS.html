Slack Integration ​

Purpose ​

Send notifications to Slack when:

  • Deployments complete (success or failure)
  • Validation errors detected
  • Scheduled syncs run

Prerequisites ​

  • Slack workspace admin access
  • GitHub repository access
  • Slack app created with chat:write scope

Setup Steps ​

  1. Create Slack App

    • Go to api.slack.com/apps
    • Create new app → From scratch
    • Name: SFCC Campaign Bot
    • Select your workspace

  2. Configure Permissions

    • OAuth & Permissions → Add scope: chat:write
    • Install to workspace
    • Copy Bot User OAuth Token

  3. Add to GitHub Secrets

    • Go to repository Settings → Secrets
    • Add secret: SLACK_BOT_TOKEN
    • Add secret: SLACK_CHANNEL_ID

  4. Add to Workflow

yaml
- name: Notify Slack
  uses: slackapi/slack-github-action@v1
  with:
    channel-id: ${{ secrets.SLACK_CHANNEL_ID }}
    slack-message: |
      :rocket: *Deployment Complete*
      • Brand: ${{ inputs.brand }}
      • Date: ${{ inputs.date }}
      • Environment: ${{ inputs.environment }}
      • Status: Success
  env:
    SLACK_BOT_TOKEN: ${{ secrets.SLACK_BOT_TOKEN }}

Microsoft Teams Integration ​

Purpose ​

Alternative to Slack for organizations using Microsoft 365.

Prerequisites ​

  • Teams admin access
  • Incoming Webhook connector

Setup Steps ​

  1. Create Incoming Webhook

    • Go to Teams channel
    • Click ••• → Connectors
    • Add Incoming Webhook
    • Name: SFCC Campaign Bot
    • Copy webhook URL

  2. Add to GitHub Secrets

    • Add secret: TEAMS_WEBHOOK_URL

  3. Add to Workflow

yaml
- name: Notify Teams
  run: |
    curl -H "Content-Type: application/json" \
      -d '{
        "@type": "MessageCard",
        "summary": "Deployment Complete",
        "sections": [{
          "activityTitle": "SFCC Deployment",
          "facts": [
            {"name": "Brand", "value": "${{ inputs.brand }}"},
            {"name": "Date", "value": "${{ inputs.date }}"},
            {"name": "Environment", "value": "${{ inputs.environment }}"}
          ]
        }]
      }' \
      ${{ secrets.TEAMS_WEBHOOK_URL }}

Jira Integration ​

Purpose ​

  • Link PRs to Jira tickets
  • Auto-update ticket status on deployment
  • Track changes per ticket

Prerequisites ​

  • Jira Cloud instance
  • Jira API token
  • GitHub-Jira app installed

Setup Steps ​

  1. Install GitHub for Jira

    • Jira Settings → Apps → GitHub for Jira
    • Connect GitHub organization

  2. Use Smart Commits

    • In commit messages, reference tickets:

      feat: Add new zone template

CAMP-123 #done
      1
      2
      3

  3. PR Title Convention

    • Include ticket number: [CAMP-123] Add homepage zone

Automation Rules ​

Create Jira automation:

  • When PR merged → Move ticket to "Done"
  • When deployment succeeds → Add comment with deployment info

PagerDuty Integration ​

Purpose ​

Alert on-call team for production issues:

  • Sync failures
  • Authentication errors
  • Rate limiting

Prerequisites ​

  • PagerDuty account
  • Service configured
  • Integration key

Setup Steps ​

  1. Create Service

    • PagerDuty → Services → New Service
    • Name: SFCC Campaign Automation
    • Escalation policy: Your team

  2. Create Integration

    • Service → Integrations → Add → Events API v2
    • Copy Integration Key

  3. Add to GitHub Secrets

    • Add secret: PAGERDUTY_INTEGRATION_KEY

  4. Add to Workflow (on failure)

yaml
- name: Alert PagerDuty
  if: failure()
  run: |
    curl -X POST https://events.pagerduty.com/v2/enqueue \
      -H "Content-Type: application/json" \
      -d '{
        "routing_key": "${{ secrets.PAGERDUTY_INTEGRATION_KEY }}",
        "event_action": "trigger",
        "payload": {
          "summary": "SFCC Deployment Failed: ${{ inputs.brand }} ${{ inputs.date }}",
          "severity": "error",
          "source": "github-actions"
        }
      }'

Adding New Integrations ​

When adding a new integration:

  1. Document in this file

    • Add to status table
    • Add setup section

  2. Add secrets to GitHub

    • Repository secrets for shared
    • Environment secrets for env-specific

  3. Update workflows

    • Add notification steps
    • Handle failures gracefully

  4. Test in staging first

    • Use staging environment
    • Verify notifications work
