Configuration Overview ​

The SFCC Campaign Automation system uses several configuration files to control behavior, define asset types, and manage brand-specific settings.

Project root files ​

Quick reference for config and tooling files at the project root. All are needed for normal development.

FilePurpose
.envEnvironment variables (SFCC, Smartsheet). Copy from .env.example. Never commit.
.env.exampleTemplate for .env; safe to commit.
.eslintrc.jsonESLint rules (extends eslint:recommended + Prettier). Test files use ESM.
.gitignoreIgnore node_modules, .env, dev-env tokens/cache, coverage, etc.
.prettierrcPrettier: semicolons, double quotes, tabWidth 2, printWidth 100.
jsconfig.jsonJS project config: @/* → src/*, checkJs, target ES2022. Excludes dev-env, docs, scripts.
package.jsonScripts, deps, engines (Node >= 18).
MakefileSource of truth for producer and dev commands (make help, make dev).

Optional / tooling: .vscode/settings.json (workspace editor settings), .vscode/extensions.json (recommended extensions). No .nvmrc or .editorconfig in this project; Node version is from package.json engines.

User Configuration ​

Environment Variables (.env) ​

Create a .env file in the project root for OCAPI credentials. Use your own values from SFCC Business Manager (or copy from .env.example and fill in):

bash
# SFCC OCAPI — replace placeholders with your instance and credentials
SFCC_BASE_URL=https://your-instance.demandware.net
SFCC_CLIENT_ID=your-client-id
SFCC_CLIENT_SECRET=your-client-secret
SFCC_SITE_ID=your-site-id
SFCC_LIBRARY_ID=your-library-id

# Smartsheet (optional)
SMARTSHEET_API_KEY=your-api-key
SMARTSHEET_SHEET_ID_LOFT=your-sheet-id
SMARTSHEET_SHEET_ID_ANN=your-sheet-id

User Preferences (.ocapi-config.json) ​

Created by make setup, stores user preferences. Shape: workspace (brand, activeSource, sources, ocapi), brandState (per-brand sticky date, status cache), meta (createdAt, updatedAt). Legacy flat keys are migrated on load.

json
{
  "workspace": {
    "brand": "loft",
    "activeSource": "local",
    "sources": {
      "local": { "type": "local", "path": "data/excel/LOFT (Converted).xlsx" },
      "smartsheet": { "type": "smartsheet", "path": "data/smartsheet", "cacheTtlMinutes": 15 }
    },
    "ocapi": { "enabled": false }
  },
  "brandState": {},
  "meta": { "createdAt": null, "updatedAt": null }
}

Application Configuration ​

sfcc.config.js ​

Combines application constants and SFCC API configuration:

  • ACTION_TYPES: LAUNCH, UPDATE, REMOVE, NO_CHANGE
  • PATH_CONSTANTS: DEV_ENV, REFRESHES, PREVIEW
  • FILE_NAMES: REFRESH_JSON, OCAPI_PAYLOAD, etc. Sync state and registry live in refresh.json (sync + registry sections) per refresh.
  • BRANDS_CONFIG: Brand definitions (environment URLs, contextIds for category-scoped assets). See Brands.

SFCC API configuration:

  • BASE_URL: SFCC API endpoint
  • API_VERSION: OCAPI version from env (default v21_10)
  • AUTH_URL: OAuth token endpoint
  • OCAPI_RUNTIME: Frozen object with all OCAPI tuning constants (rate limits, retries, timeouts, chunk size for bulk ops, cache TTL) — hardcoded, no env var overrides
  • Validation: Required environment variable checking

excel.config.js ​

Shared Excel header aliases:

  • HEADER_ALIASES: Maps 21 canonical system fields to accepted Excel column names (case-insensitive). All brands share the same aliases. To support a new column naming convention, add it to the relevant field's alias array.

asset.config.js ​

Source of truth for asset types and patterns:

  • ASSET_TYPES: PPH, POPUP, COUPONS, HOMEPAGE, PLP_HEADER, etc. (active, mode, syncStrategy, slot, template, zones)
  • ASSET_TYPE_PATTERNS, HOMEPAGE_ZONE_PATTERNS, TEMPLATE_PATTERNS: Map Excel/wireframe names to canonical types and zones

See Slots & Asset Types for how asset.config.js relates to slots.config.js.

slots.config.js ​

Imports from asset.config.js and provides resolution helpers (resolveAssetType, getSyncStrategy, etc.):

  • Slot resolution: Which SFCC slot each asset type uses
  • Zone configurations: Multi-zone asset definitions
  • Mode settings: TEMPLATE vs DEVELOPER mode

Modifying Configuration ​

User Preferences ​

Use the setup wizard:

bash
make setup
1

Environment Variables ​

Edit .env file directly or use environment:

bash
export SFCC_CLIENT_SECRET=new-secret
1

Application Config ​

Edit files in src/config/ directly. Changes take effect immediately (no build required).

WARNING

Modifying application config files affects all users. Coordinate changes with the team.

Validation ​

The system validates configuration at startup:

bash
# Check OCAPI configuration
make setup

# Check current settings
make status
