Reference for the directory structure and file locations used by the system.

Directory Structure ​

project-root/
├── dev-env/                        # Working directory
│   ├── .ocapi-config.json          # User configuration
│   ├── loft/                       # LOFT brand directory
│   │   ├── asset-registry.json     # Asset registry
│   │   └── refreshes/              # Refresh data
│   │       └── 2026-02-03/         # Date directory
│   │           ├── r1/             # Refresh 1
│   │           └── r2/             # Refresh 2 (if exists)

│   │   ├── template.html
│   │   └── zones/
│   │       ├── _layout.html
│   │       └── hp_*.html
│   └── .../
├── docs/                           # Documentation
└── src/                            # Source code

Refresh Directory ​

Each refresh has this structure:

dev-env/{brand}/refreshes/{date}/{refreshId}/
├── refresh.json           # Input: Parsed wireframe data
├── ocapi-payload.json     # Output: Campaign for OCAPI
├── sync-config.json       # Sync state + last-synced config (status + campaign/slots)
├── assets/                # Output: Asset JSON files
│   ├── {asset-id}.json
│   └── ...
└── preview/               # Output: Preview files
    ├── templates/         # Organized by asset type (zone shorthand filenames)
    │   ├── homepage/      # Homepage zone templates
    │   │   ├── hp-slots.html
    │   │   ├── hp-mobile-cats.html
    │   │   └── hp-1t-a1.html
    │   ├── pph/           # PPH templates
    │   │   └── pph.html
    │   ├── popup/         # Popup templates
    │   │   └── popup.html
    │   └── plp-header/    # PLP header templates
    │       └── plp-header.html
    └── rendered/          # Composed HTML output
        ├── homepage.html  # <!-- asset: loft-2026-02-03-r1-homepage -->
        └── pph.html       # <!-- asset: loft-2026-02-03-r1-pph -->

Template filenames use the zone shorthand (e.g., hp-mobile-cats.html) instead of the full asset ID. The SFCC asset ID is in the @asset: comment at the top of each template file.

Rendered files have an <!-- asset: ... --> HTML comment at the top showing the SFCC asset ID, type, and zone/item count.

Note: Inactive asset types (NFP, FP, etc.) are skipped during preview generation.

Key Files ​

The refresh manifest is always refresh.json (no legacy alternate filename).

refresh.json ​

Input file containing parsed wireframe data (metadata manifest; asset data lives under assets/*.json):

json
{
  "date": "2026-02-03",
  "refreshId": "r1",
  "brand": "loft",
  "assetTypes": {
    "HOMEPAGE": {
      "HP_TOP_BANNER": {
        "action": "LAUNCH",
        "headline": "Spring Sale"
      }
    }
  }
}

sync-config.json ​

Single file for sync state and last-synced config (replaces the old separate sync-status.json):

  • Status: synced, lastSyncedAt, lastAttemptAt, error, campaignId, refreshPath (and replication.steps for replicate checklist).
  • Config: campaign_id, name, description, slots (with asset content) — used for sync diff and upload-by-prefix.
json
{
  "synced": true,
  "lastSyncedAt": "2026-02-03T10:35:00.000Z",
  "lastAttemptAt": "2026-02-03T10:35:00.000Z",
  "error": null,
  "campaignId": "loft-2026-02-03-r1",
  "campaign_id": "loft-2026-02-03-r1",
  "name": "...",
  "slots": [...]
}

Path Builder Functions ​

javascript
const config = require('./config/app.config');

// Get dev-env path
config.getDevEnvPath('loft');
// → 'dev-env/loft'

// Get refreshes path
config.getRefreshesPath('loft');
// → 'dev-env/loft/refreshes'

// Get specific refresh path
config.getRefreshPath('loft', '2026-02-03', 'r1');
// → 'dev-env/loft/refreshes/2026-02-03/r1'

// Get asset registry path
config.getAssetRegistryPath('loft');
// → 'dev-env/loft/asset-registry.json'
