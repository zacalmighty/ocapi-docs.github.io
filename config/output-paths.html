Refresh Directory ​

Each refresh has this structure:

dev-env/{brand}/refreshes/{date}/{refreshId}/
├── refresh.json           # Input: Parsed wireframe data + sync section + registry section
├── ocapi-payload.json     # Output: Campaign for OCAPI
├── assets/                # Output: Asset JSON files (named by asset ID)
│   ├── {brand}-{date}-{refreshId}-{type}.json   # e.g., loft-2026-02-03-r1-homepage.json
│   └── ...
└── preview/               # Output: Preview files
    ├── templates/         # Organized by asset type (zone shorthand filenames)
    │   ├── homepage/      # Homepage zone templates
    │   │   ├── hp-slots.html
    │   │   ├── hp-mobile-cats.html
    │   │   └── hp-1t-a1.html
    │   ├── pph/           # PPH templates
    │   │   └── pph.html
    │   ├── popup/         # Popup templates
    │   │   └── popup.html
    │   └── plp-header/    # PLP header templates
    │       └── plp-header.html
    └── rendered/          # Composed HTML output (named by asset ID)
        ├── loft-2026-02-03-r1-homepage.html  # <!-- asset: loft-2026-02-03-r1-homepage -->
        └── loft-2026-02-03-r1-pph.html       # <!-- asset: loft-2026-02-03-r1-pph -->

Template filenames use the zone shorthand (e.g., hp-mobile-cats.html) instead of the full asset ID. The SFCC asset ID is in the @asset: comment at the top of each template file.

Rendered files have an <!-- asset: ... --> HTML comment at the top showing the SFCC asset ID, type, and zone/item count.

Note: Inactive asset types (NFP, FP, etc.) are skipped during preview generation.

Key Files ​

The refresh manifest is always refresh.json (no alternate filename).

refresh.json ​

Input file containing parsed wireframe data (metadata manifest; asset data lives under assets/{assetId}.json). Also includes a sync section for sync state (synced, lastSyncedAt, stale, etc.) and last-synced campaign config. Source: src/infrastructure/parsing/ExcelParser.js, src/infrastructure/filesystem/FileSystemStore.js.

json
{
  "date": "2026-02-03",
  "refreshId": "r1",
  "brand": "loft",
  "sync": {
    "synced": false,
    "lastSyncedAt": null,
    "lastSyncedConfig": null
  },
  "assetsByType": {
    "HOMEPAGE": {
      "assetType": "HOMEPAGE",
      "zones": [
        {
          "zone": "HP_TOP_BANNER",
          "items": [
            { "action": "LAUNCH", "headline": "Spring Sale" }
          ]
        }
      ]
    }
  }
}

The sync section in refresh.json holds sync state and last-synced config:

  • Status: synced, stale, staleReason, staleSince, lastSyncedAt, lastAttemptAt, error. When make pull brings new data for an already-synced refresh, the system sets stale: true, staleReason: "source-data-changed", and staleSince (ISO timestamp).
  • lastSyncedConfig: Full campaign config (campaign_id, slots) used for sync diff and upload-by-prefix.

Asset JSON ({brand}-{date}-{refreshId}-{type}.json) ​

Individual asset data files are named by their campaign ID and asset type (e.g., loft-2026-02-03-r1-homepage.json):

Path Constants ​

Defined in src/config/sfcc.config.js. Only PATH_CONSTANTS (DEV_ENV, REFRESHES, PREVIEW) and FILE_NAMES live there; subdirs such as templates/, rendered/, and assets/ are built by src/infrastructure/filesystem/pathBuilder.js (e.g. previewDir, templatesDir, and asset file paths under each refresh).

javascript
const PATH_CONSTANTS = {
  DEV_ENV: "dev-env",
  REFRESHES: "refreshes",
  PREVIEW: "preview",
};

const FILE_NAMES = {
  REFRESH_JSON: "refresh.json",
  OCAPI_PAYLOAD: "ocapi-payload.json",
  OCAPI_CONFIG: ".ocapi-config.json",
};

Path building ​

Paths are built from PATH_CONSTANTS and FILE_NAMES in config/sfcc.config and from pathBuilder.js for preview/templates/rendered/assets subdirs:

javascript
const path = require("path");
const { PATH_CONSTANTS, FILE_NAMES } = require("./config");

// Refreshes dir: dev-env/{brand}/refreshes
path.join(PATH_CONSTANTS.DEV_ENV, brand, PATH_CONSTANTS.REFRESHES);

// Refresh dir: dev-env/{brand}/refreshes/{date}/{refreshId}
path.join(PATH_CONSTANTS.DEV_ENV, brand, PATH_CONSTANTS.REFRESHES, date, refreshId);

// refresh.json (includes sync + registry sections)
path.join(refreshDir, FILE_NAMES.REFRESH_JSON);
