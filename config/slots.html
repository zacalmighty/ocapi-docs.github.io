Slots & Asset Types ​

Asset types define the categories of promotional content and how they map to SFCC slots.

Configuration Location ​

src/config/slots.config.js — Slot resolution and helpers live here. The canonical asset type definitions (ASSET_TYPES, patterns) live in asset.config.js; slots.config.js imports them and adds resolution APIs. See Asset Types Configuration.

Asset Type Schema ​

Each asset type has these properties:

PropertyTypeDescription
activebooleanWhether automation processes this type
modestringTEMPLATE, DEVELOPER, or DATA
syncStrategystringcontent-slot, plp-callout, pos-api, or data
slotobjectSFCC slot binding { id, context, categoryId? }
zonesarrayZone definitions (for multi-zone types)
wrapperClassstringCSS class for outer container div (e.g., "g3-hp")
externalResourcesobjectCSS/JS resources to include

Slot Binding ​

The slot property defines how the asset binds to an SFCC content slot:

javascript
slot: {
  id: "global-promotion-banner",  // SFCC slot ID
  context: "global",               // "global" or "category"
  categoryId: "cat1780006"         // Fixed category (optional)
}

Sync Strategy & Group Resolution ​

All asset type config lives in ASSET_TYPES; resolveAssetGroup and getSyncStrategy derive from it. Pattern-based types (PLP BANNER, PPH SLOT N, FP/NFP/SFP, etc.) resolve via ASSET_TYPE_PATTERNS.

javascript
const { resolveAssetGroup, getSyncStrategy } = require('./config/slots.config');

// Resolve to group-like info (derived from ASSET_TYPES)
resolveAssetGroup("PPH-A");  // { groupKey: "pph", group: {...} }
resolveAssetGroup("FP");     // { groupKey: "plp-promo", group: {...} }

// Get sync strategy
getSyncStrategy("PPH");      // "content-slot"
getSyncStrategy("FP");       // "plp-callout"

Mode Types ​

TEMPLATE Mode ​

HTML is generated from Handlebars templates:

templates/{asset-type}/template.html + JSON data → Rendered HTML
1
  • Templates live in templates/ directory
  • Data comes from wireframe/refresh
  • Rendering happens during refresh command

DEVELOPER Mode ​

HTML is provided directly (no template rendering):

Wireframe HTML → ContentAsset.content
1
  • Used for complex layouts (Homepage zones)
  • HTML comes from the source data
  • More flexibility, less automation

DATA Mode ​

No HTML generation — data stored for reference or separate API calls:

  • Used for PLP promo text (FP, NFP, etc.)
  • Used for miscellaneous data-only assets
  • Data accessible via JSON files

Homepage Zone Consolidation (HOMEPAGE_ZONE_PATTERNS) ​

The ExcelParser automatically consolidates standalone Excel asset types into HOMEPAGE zones:

Excel Asset TypeMaps To ZoneBehavior
HP CAT NAVHP_MOBILE_CATSMerged as items (11 labels, ordered A=1–K=11)
CAT IMAGEHP_CAT_IMAGEMerged as items (6 tiles, ordered A=1–F=6)
SLOT 1 through SLOT 4HP_SLOTSMerged into single zone (ordered)
BOTTOM BANNERHP_BOTTOM_BANNERNew zone
FEATURED SHOPSHP_FEATURED_SHOPSNew zone
RFLK WIDGETHP_RFLK_WIDGETNew zone
UGC WIDGETHP_UGC_WIDGETNew zone

After consolidation, only the HOMEPAGE asset remains with all zones — no standalone cat-a.json, slot-1.json, etc.

API Functions ​

javascript
const slots = require('./config/slots.config');

// Get asset type config
const config = slots.getAssetTypeConfig('HOMEPAGE');

// Check if active
slots.isActive('PPH');  // true

// Get HTML source type
slots.getHtmlSource('PPH');      // 'TEMPLATE'
slots.getHtmlSource('HOMEPAGE'); // 'DEVELOPER'

// Get zones for multi-zone type
slots.getZonesForType('HOMEPAGE'); // ['HP_MOBILE_CATS', 'HP_HERO', ...]

// Resolve asset group
slots.resolveAssetGroup('FP DENIM');  // { groupKey: 'plp-promo', group: {...} }

// Get sync strategy
slots.getSyncStrategy('PPH');  // 'content-slot'
slots.getSyncStrategy('FP');   // 'plp-callout'
