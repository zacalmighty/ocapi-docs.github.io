Brands Configuration ​

The system supports multiple brands with brand-specific configuration for environment URLs, default settings, and data sources.

Supported Brands ​

BrandKeyStatus
LOFTloftProduction ready
Ann TaylorannProduction ready

Brand Configuration ​

Defined in src/config/sfcc.config.js:

javascript
const BRANDS_CONFIG = {
  loft: {
    name: "LOFT",
    qa_link: "https://qa.loft.com",
    stg_link: "https://stg.loft.com",
    stg_test_link: "https://stg-test.loft.com",
    prod_link: "https://www.loft.com",
    contextIds: { COUPONS: "cat1780006" },  // category-scoped asset types
  },
  ann: {
    name: "Ann Taylor",
    qa_link: "https://qa.anntaylor.com",
    stg_link: "https://stg.anntaylor.com",
    stg_test_link: "https://stg-test.anntaylor.com",
    prod_link: "https://www.anntaylor.com",
    contextIds: { COUPONS: "cat1510004" },  // category-scoped asset types
  },
};

Context IDs (category-scoped assets) ​

Some asset types (e.g. COUPONS) are category-scoped and use different category IDs per brand. These live in contextIds:

BrandAsset TypeCategory ID
LOFTCOUPONScat1780006
Ann TaylorCOUPONScat1510004

Preview URLs for category pages (e.g. COUPONS, PLP_HEADER) will be resolved dynamically once CategoryService is implemented. Until then, slot resolution uses contextIds only.

Switching Brands ​

Use make switch to toggle loft ↔ ann (no args), or make switch BRAND=ann for a specific brand. Use make setup for the full wizard.

Per-Command Brand Override ​

bash
make refresh BRAND=loft DATE=2026-02-03
make refresh BRAND=ann DATE=2026-02-03

SFCC Configuration per Brand ​

SFCC credentials are brand-agnostic in the .env file, but SFCC_SITE_ID and SFCC_LIBRARY_ID should match the target brand:

bash
# For LOFT
SFCC_SITE_ID=Loft
SFCC_LIBRARY_ID=Library - Loft

# For Ann Taylor
SFCC_SITE_ID=AnnTaylor
SFCC_LIBRARY_ID=Library - AnnTaylor

Excel Header Mapping ​

Excel column-to-field mapping is shared across all brands and defined in src/config/excel.config.js via the HEADER_ALIASES constant. This ensures consistency and reduces duplication:

javascript
// src/config/excel.config.js
const HEADER_ALIASES = Object.freeze({
  STATUS: ["STATUS"],
  REFRESH_NAME: ["REFRESH_NAME", "REFRESH NAME", "PROJECT SUMMARY"],
  ASSET_TYPE: ["ASSET_TYPE", "ASSET TYPE"],
  // ... all 21 canonical field mappings
});

Each key is a canonical field name used internally by ExcelParser. The value is an array of accepted Excel column names (aliases). To support a new column naming convention, add it to the relevant field's alias array in excel.config.js.

Adding a New Brand ​

To add a new brand:

  1. Add to BRANDS_CONFIG in sfcc.config.js:
javascript
newbrand: {
  name: 'New Brand',
  qa_link: 'https://qa.newbrand.com',
  stg_link: 'https://stg.newbrand.com',
  stg_test_link: 'https://stg-test.newbrand.com',
  prod_link: 'https://www.newbrand.com',
  ipidSegment: 'newbrand',
  sfccDefaults: { siteId: 'NewBrand', libraryId: 'NewBrand' },
  contextIds: { COUPONS: 'cat...' },  // if using category-scoped asset types
},

Makefile Brand Variables ​

The Makefile auto-detects the Excel file based on the BRAND variable:

VariablePurposeValue
BRANDActive brand (loft or ann)Read from config or env
BRAND_EXCELAuto-resolved Excel pathdata/excel/LOFT (Converted).xlsx or data/excel/Ann (Converted).xlsx
EXCEL_FILEOverride pathFrom config or fallback to BRAND_EXCEL

BRAND_EXCEL is computed in the Makefile as:

makefile
BRAND_EXCEL = $(shell node -e "console.log('$(BRAND)'==='ann'?'data/excel/Ann (Converted).xlsx':'data/excel/LOFT (Converted).xlsx')")
1

The ensure-config target automatically updates the config file when the BRAND changes, so switching brands always uses the correct Excel source.
