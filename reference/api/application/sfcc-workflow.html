SfccWorkflow - SFCC sync operations. ​

SfccWorkflow - SFCC sync operations.

This module provides:

  • SyncToSfcc: Sync and upload campaigns/assets to SFCC via OCAPI

SyncToSfcc synchronizes a campaign to SFCC via OCAPI.

This use case handles the complete synchronization workflow:

  • Campaign metadata creation/update
  • Content asset upload
  • Slot configuration and binding
  • Asset renaming and cleanup

Group: application

Constructor ​

ParameterTypeDescription
brandobjectBrandContext instance

Methods ​

execute(campaign, options, options.skipAssets, options.skipSlots, options.skipDev, options.forceDev, options.dryRun) ​

Execute campaign sync (create or update) with OCAPI.

Performs a complete synchronization of a campaign to SFCC:

  1. Validates the campaign structure
  2. Compares with previously synced version
  3. Uploads changed content assets
  4. Creates/updates slot configurations
  5. Binds slots to the campaign
ParameterTypeDescription
campaignCampaignThe campaign domain entity to sync
optionsobjectConfiguration options
options.skipAssetsbooleanSkip asset synchronization
options.skipSlotsbooleanSkip slot synchronization
options.skipDevbooleanSkip dev file generation
options.forceDevbooleanForce dev file regeneration
options.dryRunbooleanSimulate without making changes

Returns: Promise&lt;SyncResult&gt; — Results with config and sync details

_saveAsset(asset) ​

Save a content asset to SFCC via the asset service.

Retry logic is handled entirely by ApiClient (OCAPI_RUNTIME.maxRetries attempts with exponential backoff). No additional retry layer here to avoid stacking retries (which could cause up to 12 HTTP attempts).

ParameterTypeDescription
assetobjectContentAsset to save

Returns: Promise&lt;void&gt;

_routeBySyncStrategy(slots) ​

Route slots by sync strategy before syncing.

Separates slots into groups based on their syncStrategy:

  • content-slot: Standard SFCC content slot (OCAPI) — handled here
  • plp-callout: PLP promotional text — logged for separate handling
  • pos-api: POS messaging — logged as stub for future
  • data: Data-only — skipped for slot sync
ParameterTypeDescription
slotsArrayArray of slot configurations

Returns: Object

_fanOutCategorySlots(slots) ​

Fan out category-scoped slots.

For slots with categoryIds, creates one binding per category ID with context: "category" and context_id set to the category.

ParameterTypeDescription
slotsArrayArray of slot configurations

Returns: Array — Expanded slots with category fanout applied

_expandSlotsForSync(allSlots) ​

Route slots by sync strategy and expand category-scoped content slots for sync.

ParameterTypeDescription
allSlotsArrayAll slot configurations from OCAPI payload

Returns: Object

uploadByPrefix(assetPrefix, options) ​

Upload all local assets that differ from OCAPI based on prefix.

ParameterTypeDescription
assetPrefixstringAsset prefix to match
optionsobjectUpload options

Returns: Promise&lt;Object&gt; — Upload results (SyncResult shape)

Example ​

javascript
// Basic sync workflow
const brand = new BrandContext("loft");
const campaign = brand.usecases.compileRefresh.execute(refresh);
const result = await brand.usecases.syncToSfcc.execute(campaign);
console.log(result.results.assets.created); // ["loft-2026-01-26-r1-homepage"]

// Sync with options
await brand.usecases.syncToSfcc.execute(campaign, {
  skipSlots: true,      // Only sync assets, not slots
  skipDev: true,        // Skip dev file generation
  dryRun: false         // Actually perform the sync
});

// Upload by prefix (partial sync)
const result = await brand.usecases.syncToSfcc.uploadByPrefix("loft-2026-01-26");
console.log(result.results.updatedAssets); // Assets that were uploaded

const result = await syncToSfcc.execute(campaign);
if (result.results.skipped) {
  console.log("No changes to sync");
} else {
  console.log(`Created: ${result.results.assets.created.length} assets`);
  console.log(`Updated: ${result.results.assets.updated.length} assets`);
}
