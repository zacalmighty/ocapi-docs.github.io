Command Reference ​

Quick reference for all Makefile commands. For full syntax, flags, and example output, use the per-command pages under Commands.

Command summary ​

CommandWhat it does
make setupConfigure brand, data source, and SFCC (OCAPI). Runs a wizard and saves config.
make switch [BRAND=]Toggle brand (no arg: loft ↔ ann). Or make switch BRAND=ann for specific brand.
make pullGit pull, fetch latest data (Excel/Smartsheet), auto-build new dates. Does not open status — run make status after.
make refreshBuild selected refresh (dev files + payload).
make pushValidate and sync selected refresh(es) to SFCC staging.
make statusInteractive hub: pick a refresh and run core actions (build, push, upload, delete, detail, pull).
make delete DATE=Remove a refresh from SFCC and locally. DATE= is required to delete; omit DATE (run make delete with no args) to list deletable refreshes. Use REFRESH=r1 when the date has multiple refreshes.
make uploadPartial asset sync (HTML changes only).
make reports [OP=coverage]Visibility reports: report (per-refresh zone/IPID table), history (zone timeline), coverage (IPID coverage).
make testRun all tests. Use test-watch for watch mode and test-coverage for coverage.
make fresh-installFull reset: remove dev-env and node_modules, reinstall, then run tests.
make convert-excel INPUT=Convert raw Excel to CONVERTED format (INPUT required).
make checkLint, tests, and audit (CI gate).
make cleanRemove rendered previews.
make docsGenerate API docs and start the docs dev server.
make docs-genRegenerate API and template reference docs.
make docs-buildGenerate docs and build the static site.
make docs-deployBuild and deploy docs to GitHub Pages.
make lint-docsLint action types in doc files.
make test-sync DATE=Push to OCAPI with auto-confirm (for CI).
make build-all [FORCE=1]Build every date for the current brand.
make push-all [YES=1] [FORCE=1]Sync every date to SFCC (run after build-all).
make doctorValidate setup, config, brand, source, refresh dirs, and OCAPI env. Also prints config summary.
⚠️ Destructive / test-use-only commands (not for routine producer use)

These commands can delete data, overwrite many campaigns, or wipe local state. For testing or when explicitly directed; do not use in normal workflow.

CommandRisk
make fresh-installDestructive. Removes dev-env and node_modules, then reinstalls. All local state and built data are lost.
make delete DATE=...Destructive. Removes a refresh from SFCC and locally. Can remove live or synced content. Requires DATE=; use REFRESH=r1 if the date has multiple refreshes.
make push-all [YES=1]Loose cannon. Pushes every date for the brand to SFCC. With YES=1 there are no confirmation prompts. Use only for CI or when a developer directs.
make test-syncTesting only. Sync with auto-confirm (--yes --force). For CI/automation, not daily use.
make docs-deployPublishing. Deploys docs to GitHub Pages. Only the doc owner should run this.
make cleanRemoves all rendered preview files. Use only if a developer asks you to free space or reset previews.
make build-all [FORCE=1]Rebuilds every date for the brand. Batch/dev use; not for normal producer workflow.
make convert-excel INPUT=...Converts raw Excel; can overwrite files. Dev-only.

Flags to avoid unless a developer tells you: Do not use YES=1 (skips all approval prompts) or FORCE=1 (bypasses "already built" / "already synced" guards) unless a developer explicitly asks you to.

Test commands: Run make test for the full suite. Use make test-watch for watch mode and make test-coverage for coverage. Use make fresh-install for a full reset (deps + dev-env) then tests. To run a subset by path: npx vitest run tests/domain or npx vitest run tests/cli.

Approval guards: When data has already been built or synced and you run make push again, the tool shows what changed and asks for approval. Use FORCE=1 to skip the prompt (e.g., in CI). Use YES=1 to auto-approve.

build-all / push-all: For dev/CI batch runs. Run make pull first (auto-builds new dates); then make build-all to rebuild all dates; then make push-all to sync all of them to SFCC. Use YES=1 to skip confirmation prompts. Use FAIL_FAST=1 to stop on first failure (default: continue on error).

Automation: For scripts and CI, use DATE=, REFRESH=, YES=1, FORCE=1 as needed. Use VERBOSE=1 for run IDs on log lines. Use FAIL_FAST=1 for fail-fast batch runs, and ARGS="..." to pass extra CLI flags.

Make variables → CLI flags ​

The Makefile is the source of truth. All commands are invoked via make <target>; the CLI receives variables as flags.

Make variableCLI flag / behaviourExample
BRANDFirst positional arg (defaults to config brand); for make switch: target brand (omit to toggle)make pull; make switch BRAND=ann
DATE--date=YYYY-MM-DDmake refresh DATE=2026-02-14
REFRESH--refresh=r1make push REFRESH=r2
FORCE=1--force (force rebuild/re-push; skip delete confirmation)make push FORCE=1; make delete DATE=… FORCE=1
YES=1--yes (skip confirmation/approval prompts)make push-all YES=1
ALL=1refresh/push: --all-refreshes (all refreshes in a date); status: --all (full history)make status ALL=1
FAIL_FAST=1Stop build-all/push-all on first failure (default: continue)make build-all FAIL_FAST=1
ARGS="..."Pass extra CLI flags (appended after mapped vars)make push ARGS="--yes --force"
SKIP_FETCH=1--skip-fetchmake pull SKIP_FETCH=1
CONVERT=1--convertmake pull CONVERT=1
STATUS_REFRESH_INDEXstatus (non-TTY): 0-based index of refresh row to act onSTATUS_REFRESH_INDEX=2 make status
STATUS_ACTION_INDEXstatus (non-TTY): 0-based index of action (0=Build refresh, 1=Push to staging, 2=Upload assets, 3=Delete refresh, 4=Refresh detail, 5=Pull).STATUS_ACTION_INDEX=1 make status
VERBOSE=1--verbosemake push VERBOSE=1
OPreports operation (report, history, coverage)make reports OP=report DATE=2026-02-14

Brand switch: Use make switch to toggle loft ↔ ann (no args). Use make switch BRAND=ann for a specific brand. Use make setup for full wizard.

Shared CLI flags ​

Most commands support: --force, -y/--yes, --dry-run, --verbose, --date, --refresh, --no-interactive, --strict. See per-command pages for command-specific flags. Run make <command> ARGS="--help" for full usage.

CLI arguments ​

Most commands take [brand] [target] — brand (loft, ann) and target (date, path, or operation). Brand defaults to config; target varies by command (date/path for refresh/push, campaign prefix for upload, zone for reports history). Use make <command> ARGS="--help" to see per-command args.
