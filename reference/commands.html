Command Reference ​

Quick reference for all Makefile commands. For full syntax, flags, and example output, use the per-command pages under Commands.

Command summary ​

StepCommandWhat it doesTypical output
Setupmake setupConfigure brand, data source, OCAPIWizard; writes dev-env/.ocapi-config.json
Setupmake switch TO=annSwitch brandUpdates config for Ann Taylor
Setupmake healthTest SFCC connection✔ OCAPI ready (NNNms) or missing-env errors
1make pullGit sync + fetch + pick dateFetch results; date picker; "Next: make build"
2make selectSet active refresh (sticky)✔ Selected YYYY-MM-DD / r1 or picker
3make buildGenerate HTML + OCAPI payload✔ N files generated or "Already built" / "Already synced"
4make build FORCE=1Force rebuild (bypass guard)Same as build
5make previewShow preview linksLinks per asset type; Section Picker
6make pushValidate + sync to SFCC✔ Synced …: X created, Y updated or "no changes to sync"
7make replicateStaging → production checklistChecklist; "Next: make email"
8make emailGenerate changeout emailEmail body (make done is alias)
9make commitSave to Git (refresh dir only)✔ Committed: brand date done
Statusmake statusDashboard + action picker; selection sets activeSummary + picker (TTY) or full table
Devmake delete DATE=Remove refresh from SFCC + local✔ SFCC deleted / ✔ Deleted local
Devmake uploadPartial asset sync (hotfix)Sync summary
Devmake registryShow live asset registryZone list + item counts
Devmake registry-ipidsList all IPIDs in the registryAsset type, zone, order, IPID
Devmake testRun unit tests (Vitest)Tests N passed
Devmake checkLint + tests + audit (CI gate)Lint + test + audit output
Devmake cleanRemove rendered previews✔ Cleaned
Devmake docsStart docs dev serverVitePress URL
Devmake reports [OP=dates]Report: dates, stats, status, pending, historySee reports
Devmake validate [DATE=]Data quality check only (no build/push)See validate
CImake test-sync DATE=Push to OCAPI with --yes --force (CI / non-interactive)Sync output
CImake build-all [FORCE=1]Build every date for current brand (no watcher)Per-date build output
CImake push-all [YES=1] [FORCE=1]Sync every date to SFCC (run after build-all)Per-date sync output

build-all / push-all: For CI or batch runs. Run make pull first; then make build-all builds all dates without starting the file watcher; then make push-all syncs all of them to SFCC. Use YES=1 to skip confirmation prompts.

Push behavior: Once a refresh is synced, make push for that refresh exits with "SFCC already has this date; no changes to sync". Use make push FORCE=1 to re-push (e.g. after hotfix). Next step after push: make replicate.

Automation: For scripts and CI, use DATE=, REFRESH=, YES=1, FORCE=1 as needed. Use VERBOSE=1 for run IDs on log lines.

Make variables → CLI flags ​

The Makefile is the source of truth. All commands are invoked via make <target>; the CLI receives variables as flags.

Make variableCLI flag / behaviourExample
BRANDFirst positional arg after commandmake build → node … refresh loft
DATE--date=YYYY-MM-DDmake build DATE=2026-02-14
REFRESH--refresh=r1make push REFRESH=r2
FORCE=1--forcemake build FORCE=1
YES=1--yesmake push-all YES=1
ALL=1 or ALL--all-refreshes or --show-allmake status ALL=1
SKIP_FETCH=1--skip-fetchmake pull SKIP_FETCH=1
CONVERT=1--convertmake pull CONVERT=1
VERBOSE=1--verbosemake push VERBOSE=1
COPY=1--copymake email COPY=1
TO(switch target)make switch TO=ann
OP(reports operation)make reports OP=stats (default: dates)
