Asset Types: Configuration & Adding New Types ​

How Excel/Smartsheet data flows into the system and how to manage asset types.

Data Flow: Excel → Refresh → Campaign → OCAPI ​

│ 1. SOURCE (Local Excel or Smartsheet)                                       │
├─────────────────────────────────────────────────────────────────────────────┤
│   Local:      path/to/file.xlsx  (DataSources.LocalExcelSource)             │
│   Smartsheet: sheet ID + API     (DataSources.SmartsheetSource → .xlsx)     │
└─────────────────────────────────────────────────────────────────────────────┘
                                        │
                                        ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│ 2. PARSE (ExcelParser)                                                      │
├─────────────────────────────────────────────────────────────────────────────┤
│   • Sheet detection: CONVERTED | BANNER | FLAT_TIMED                        │

│   • Rows → items with ASSET_TYPE, ZONE, ACTION, COPY_MESSAGE, etc.          │
│   • resolveAssetType(raw) → canonical key (PPH, HOMEPAGE, etc.)             │

Excel Column → Slot Config Mapping ​

Excel ColumnUsed ByResolution
ASSET_TYPEExcelParserresolveAssetType(raw) → canonical key (PPH, HOMEPAGE, etc.)
SITE_LOCATIONExcelParserCan override ASSET_TYPE when placement-style (e.g. "TOPS PLP/HP_HERO")
ZONEExcelParserZone within asset type; normalized to HP_* for homepage
ACTIONAllLAUNCH, NO_CHANGE, UPDATE, REMOVE, SKIP
COPY_MESSAGERenderingMarketing copy
DESTINATION_*RenderingLink target

Asset Type Resolution Chain ​

  1. Direct match: Raw string (normalized) equals an ASSET_TYPES key
  2. Underscore/space variants: PPH_HEADER ↔ PPH HEADER normalization
  3. ASSET_TYPE_PATTERNS: Excel variants → canonical (e.g. DISCLAIMER → POPUP, FP → PLP_PROMO)
  4. HOMEPAGE_ZONE_PATTERNS: Standalone Excel types (CAT A, SLOT 1, etc.) → merge into HOMEPAGE zone

Adding a New Asset Type ​

Step 1: Add to slots.config.js ASSET_TYPES ​

javascript
MY_NEW_ASSET: {
  active: true,                       // Set false to "hold" until ready
  mode: "TEMPLATE",                   // TEMPLATE | DEVELOPER | DATA
  syncStrategy: "content-slot",       // content-slot | plp-callout | data
  slot: { id: "my-slot-id", context: "global" },
  template: "my-asset/template",
  // Optional:
  zones: ["ZONE_A", "ZONE_B"],        // Multi-zone
  categoryMapping: { ... },           // For category-scoped
  externalResources: { stylesheets: [...], scripts: [...] },
  notes: "Description for future maintainers",
},

Active vs Inactive ​

| active: true | Processed by build/preview/sync | | active: false | Parsed but skipped; no HTML, no OCAPI |

Use active: false when:

  • Slot doesn't exist on SFCC yet
  • Template is not ready
  • Asset type is for future phases
