Operations Runbook ​

Operational procedures for daily producer work and incident recovery.

Daily Routine ​

bash
make pull
make status            # pick refresh (sets active) + run action
make build
make preview
make push              # auto-generates email and prints replicate steps
make commit

Multi-Refresh Rule ​

For dates with multiple refreshes:

  • use make status to pick a refresh (sets active), or make status DATE=YYYY-MM-DD/r#
  • or pass explicit REFRESH=r#
  • use ALL=1 only when intentionally processing every refresh in a date

Pre-Push Checklist ​

  • preview reviewed (make preview)
  • health verified (make health)
  • target is staging

Template Editing Workflow ​

bash
make build DATE=2026-01-26 REFRESH=r1 FORCE=1
make preview DATE=2026-01-26 REFRESH=r1
make push DATE=2026-01-26 REFRESH=r1

Changeout on a Synced Refresh ​

When make pull brings new data for a refresh that was already pushed to SFCC, the system automatically marks it UPDATED (stale). The status dashboard shows the ↻ icon in yellow.

No special flags are needed:

bash
make pull          # detects new data, marks refresh as UPDATED
make build         # proceeds automatically: "🔄 New data detected since last sync — rebuilding."
make push          # proceeds automatically: "🔄 Re-syncing — source data changed since last push." (auto-generates email)
make commit
1
2
3
4

If the pull brings identical data (no changes), the refresh stays SYNCED and the guards remain active — you still need FORCE=1 for manual overrides like template-only changes.

Common Failures ​

No refresh found ​

bash
make pull
make status
1
2

OCAPI not enabled / auth failures ​

bash
make setup
make health
1
2

Data quality or payload validation failure ​

  • fix source/template issue
  • run make pull (if source data changed)
  • re-run make build then make push

Recovery ​

Containment + restore ​

  1. disable affected campaign/assignment in Business Manager
  2. rebuild known-good refresh
  3. push known-good refresh
  4. verify storefront, then resume schedule

CLI Exit Codes ​

When running make commands, the process exits with:

CodeMeaningTypical cause
0SuccessCommand completed without error
1Validation errorInvalid input, missing required fields, schema/refresh validation failed
2Sync errorOCAPI failure, network/timeout, slot or asset sync failed
3Auth errorOCAPI 401/403, missing or invalid SFCC credentials

Use these in scripts or CI (e.g. if [ $? -eq 1 ]; then ...).

Release / Launch Checklist ​

Before tagging a release or handing off to producers:

  1. Smoke test: Run make help, then make setup (or ensure config exists), make pull, make build, make preview for at least one date.
  2. Quality: Run make check (lint + tests).
  3. Docs: Run make docs-build to ensure VitePress builds.
  4. OCAPI (if used): Set env vars from .env.example, run make health; optionally run make push with YES=1 on a test date.
  5. Changelog: Update version in package.json and note changes.
