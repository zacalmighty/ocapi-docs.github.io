GitHub Workflow Guide ​

Complete guide for launching the SFCC Campaign Automation on GitHub with CI/CD and daily Smartsheet workflow.

Overview ​

This guide covers:

  • Initial GitHub repository setup
  • GitHub Actions for CI/CD
  • Daily workflow from Smartsheet to production
  • Team collaboration via Pull Requests

Phase 1: Initial GitHub Setup ​

Step 1: Create GitHub Repository ​

  1. Go to GitHub.com
  2. Click New repository
  3. Configure:
    • Name: sfcc-campaign-automation
    • Visibility: Private (recommended)
    • Do NOT initialize with README

Step 2: Push Existing Code ​

bash
# Navigate to project directory
cd /path/to/loft-ocapi

# Initialize git if needed
git init

# Add GitHub remote
git remote add origin https://github.com/YOUR-ORG/sfcc-campaign-automation.git

# Create main branch
git branch -M main

# Stage and commit
git add .
git commit -m "Initial commit: SFCC Campaign Automation"

# Push to GitHub
git push -u origin main

Phase 2: GitHub Actions Workflows ​

Create these files in .github/workflows/:

CI Workflow (ci.yml) ​

Runs automatically on every Pull Request:

yaml
name: CI

on:
  pull_request:
    branches: [main]
  push:
    branches: [main]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      
      - uses: actions/setup-node@v4
        with:
          node-version: '18'
          cache: 'npm'
      
      - run: npm ci
      - run: npm run lint
      - run: npm test
      - run: npm run docs:build

Docs Deployment (docs.yml) ​

Auto-deploys documentation to GitHub Pages:

yaml
name: Deploy Docs

on:
  push:
    branches: [main]
    paths: ['docs/**', 'templates/**', 'scripts/generate-*.js']
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

jobs:
  deploy:
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '18'
          cache: 'npm'
      - run: npm ci
      - run: npm run docs:gen:templates
      - run: npm run docs:build
      - uses: actions/configure-pages@v4
      - uses: actions/upload-pages-artifact@v3
        with:
          path: docs/.vitepress/dist
      - uses: actions/deploy-pages@v4
        id: deployment

Campaign Workflow (campaign.yml) ​

Manual trigger for running campaign commands:

yaml
name: Campaign Workflow

on:
  workflow_dispatch:
    inputs:
      action:
        description: 'Workflow step'
        required: true
        type: choice
        options:
          - '1-pull'
          - '2-build'
          - '3-preview'
          - '4-push'
          - '5-create-pr'
          - 'reports'
          - 'email'
      brand:
        description: 'Brand'
        required: true
        type: choice
        options:
          - loft
          - ann
      date:
        description: 'Date (YYYY-MM-DD)'
        required: false

env:
  SMARTSHEET_API_KEY: ${{ secrets.SMARTSHEET_API_KEY }}
  SMARTSHEET_SHEET_ID_LOFT: ${{ secrets.SMARTSHEET_SHEET_ID_LOFT }}
  SMARTSHEET_SHEET_ID_ANN: ${{ secrets.SMARTSHEET_SHEET_ID_ANN }}

jobs:
  run:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          token: ${{ secrets.GITHUB_TOKEN }}
      
      - uses: actions/setup-node@v4
        with:
          node-version: '18'
          cache: 'npm'
      
      - run: npm ci

      - name: Pull (fetch from Smartsheet)
        if: inputs.action == '1-pull'
        run: |
          $(node src/cli/index.js excel ${{ inputs.brand }} --mode=auto --persist)

      - name: Build (generate HTML + payload)
        if: inputs.action == '2-build'
        run: |
          DATE_ARG=""
          [ -n "${{ inputs.date }}" ] && DATE_ARG="DATE=${{ inputs.date }}"
          make build BRAND=${{ inputs.brand }} $DATE_ARG

      - name: Preview
        if: inputs.action == '3-preview'
        run: |
          DATE_ARG=""
          [ -n "${{ inputs.date }}" ] && DATE_ARG="DATE=${{ inputs.date }}"
          make preview BRAND=${{ inputs.brand }} $DATE_ARG

      - name: Push (validate + sync to SFCC)
        if: inputs.action == '4-push'
        run: |
          DATE_ARG=""
          [ -n "${{ inputs.date }}" ] && DATE_ARG="DATE=${{ inputs.date }}"
          make push BRAND=${{ inputs.brand }} $DATE_ARG --yes

      - name: Create PR
        if: inputs.action == '5-create-pr'
        run: |
          BRANCH="campaign/${{ inputs.brand }}-${{ inputs.date || 'latest' }}-$(date +%Y%m%d%H%M%S)"
          git config user.name "github-actions[bot]"
          git config user.email "github-actions[bot]@users.noreply.github.com"
          git checkout -b $BRANCH
          git add dev-env/
          git commit -m "Campaign: ${{ inputs.brand }} ${{ inputs.date || 'latest' }}" || echo "No changes"
          git push -u origin $BRANCH
          gh pr create \
            --title "Campaign: ${{ inputs.brand }} ${{ inputs.date || 'latest' }}" \
            --body "Auto-generated campaign content from Smartsheet." \
            --base main
        env:
          GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}

      - name: Status
        if: inputs.action == 'status'
        run: node src/cli/index.js status ${{ inputs.brand }}

      - name: Done (email)
        if: inputs.action == 'done'
        run: |
          DATE_ARG=""
          [ -n "${{ inputs.date }}" ] && DATE_ARG="--date=${{ inputs.date }}"
          node src/cli/index.js email ${{ inputs.brand }} $DATE_ARG

      - name: Upload output
        uses: actions/upload-artifact@v4
        if: always()
        with:
          name: ${{ inputs.brand }}-${{ inputs.action }}-${{ inputs.date || 'latest' }}
          path: dev-env/${{ inputs.brand }}/
          retention-days: 30

Phase 3: Daily Workflow ​

Workflow Diagram ​

Step-by-Step Process ​

Morning: Producer Updates Smartsheet ​

  1. Producer opens Smartsheet wireframe
  2. Updates content for target date
  3. Sets action column: LAUNCH, UPDATE, NO CHANGE, etc.
  4. Notifies team: "Smartsheet updated for YYYY-MM-DD"

Step 1: Pull (Fetch Data from Smartsheet) ​

Who: Producer or Dev
Where: GitHub → Actions → Campaign Workflow

  1. Go to repo Actions tab
  2. Click "Campaign Workflow" on left sidebar
  3. Click "Run workflow" button
  4. Select:
    • Action: 1-pull
    • Brand: loft
    • Date: (leave empty)
  5. Click Run workflow
  6. Wait for green checkmark

Step 2: Build (Generate HTML + Payload) ​

  1. Run workflow again:
    • Action: 2-build
    • Brand: loft
    • Date: 2026-02-03
  2. Wait for completion

Step 3: Preview ​

  1. Run workflow:
    • Action: 3-preview
    • Brand: loft
    • Date: 2026-02-03
  2. When complete, click on the workflow run
  3. Scroll to Artifacts section
  4. Download the artifact zip
  5. Extract and open preview HTML in browser

Step 4: Push (Validate + Sync to SFCC) ​

  1. Run workflow:
    • Action: 4-push
    • Brand: loft
    • Date: 2026-02-03
  2. Check logs — data quality validation runs automatically
  3. If validation fails, fix data and re-fetch

Step 5: Create Pull Request ​

  1. Run workflow:
    • Action: 5-create-pr
    • Brand: loft
    • Date: 2026-02-03
  2. Go to Pull requests tab
  3. New PR appears automatically with generated files

Step 6: Review & Approve PR ​

Who: Dev or Lead

  1. Open the Pull Request
  2. Review the Files changed tab
  3. Download artifact to preview locally if needed
  4. Add comments or request changes
  5. Click Approve when ready

Step 7: Merge to Main ​

  1. Click "Merge pull request"
  2. Click "Confirm merge"
  3. Optionally delete the branch
  4. Docs auto-deploy to GitHub Pages

Step 8: Sync to SFCC ​

Who: Dev with local environment

bash
# Pull latest from main
git pull origin main

# Push to SFCC staging (validates automatically)
make push BRAND=loft DATE=2026-02-03

# Verify on staging site
open https://stg.loft.com

Running a Workflow ​

  1. Click Actions tab
  2. Select workflow from left sidebar
  3. Click "Run workflow" dropdown (right side)
  4. Fill in the form inputs
  5. Click green "Run workflow" button
  6. Click on the running workflow to watch progress
  7. Download artifacts when complete

Branch Protection Rules ​

Configure in Settings → Branches → Add rule:

RuleRecommended Setting
Branch name patternmain
Require pull request before merging✅
Required approving reviews1
Require status checks to pass✅ (test job)
Require branches to be up to date✅
Include administrators✅

Troubleshooting ​

Common Issues ​

IssueCauseSolution
Fetch failsSmartsheet secrets not setAdd secrets in Settings
Generate failsDate not in fetched dataRun fetch first, check date exists
Validate failsTemplate syntax errorsCheck logs, fix templates
PR has no changesContent unchangedNormal if no updates
Can't download artifactsWorkflow still runningWait for completion
Pages not deployingPages not enabledEnable in Settings → Pages

Checking Workflow Logs ​

  1. Go to Actions tab
  2. Click on the workflow run
  3. Click on the job name
  4. Expand each step to see logs
  5. Look for red ❌ to find failures
