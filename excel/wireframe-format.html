Wireframe format ​

This page defines the wireframe format the CLI expects. Use it when preparing or editing the Excel file.

Supported Excel formats ​

The system auto-detects the format based on column headers:

FormatWhen to useDetection
CONVERTEDStandard (recommended)Has REFRESH_NAME, REFRESH_DATE, ACTION, ASSET_TYPE, SITE_LOCATION
BANNERLegacy LOFT formatHas WEB_PROD_CODED, DEVICE with date patterns
FLAT_TIMEDTimed refreshesHas REFRESH_DATE, START_DATETIME, ACTION

CONVERTED format (recommended) ​

REFRESH NAMEName of the refresh"1/26 Winter Sale"

Sheet structure: parent-child rows ​

  • Parent row: Has REFRESH NAME and DATE; no ASSET TYPE.
  • Child rows: Have ACTION, ASSET TYPE, ZONE; they inherit date from the parent.

                 │           │ NO_CHANGE │ PPH     │ PPH      ← Child

Action types ​

ActionMeaningSystem behavior
LAUNCHNew contentGenerates new HTML, registers in asset registry
UPDATEModify existingRe-renders HTML, syncs updated content to SFCC
REMOVEDelete contentUnregisters zone, deletes from SFCC
NO_CHANGESame as beforeReuses asset from registry, no new files

Example: one row → one asset ​

A single child row with ACTION=LAUNCH, ASSET_TYPE=PPH, ZONE=PPH, COPY=50% off winter becomes one content asset in the refresh JSON under assetsByType.PPH. After build, it appears in the PPH template output and in the OCAPI payload for that slot.

Example: rows → JSON structure ​

Here are two sample Excel rows (child rows under a parent with REFRESH NAME and DATE) and the shape of the parsed refresh JSON they produce.

Excel rows (CONVERTED format):

REFRESH NAMEDATEACTIONASSET TYPEZONECOPYDESTINATION ID
1/26 Winter Sale1/26/2026LAUNCHHOMEPAGEHP_HERO50% off winter/sale/winter
1/26 Winter Sale1/26/2026LAUNCHPPHPPHFree shipping/shipping

Resulting structure in refresh.json (simplified):

  • campaign.refresh.date = "2026-01-26", campaign.refresh.name = from parent row.
  • assetsByType.HOMEPAGE.zones = one zone object with zone: "HP_HERO", items: [{ action: "LAUNCH", copy: "50% off winter", destination: "/sale/winter", ... }].
  • assetsByType.PPH.zones = one zone with zone: "PPH", items: [{ action: "LAUNCH", copy: "Free shipping", destination: "/shipping", ... }].

After make build, each zone gets rendered HTML and an asset ID (and IPID for LAUNCH). The OCAPI payload then includes these assets and their slot bindings.

Site locations and zones ​

Asset types (HOMEPAGE, PPH, POPUP, COUPONS, PLP_HEADER, etc.) and their zones are defined in config. Homepage zones (e.g. HP_TOP_BANNER, HP_2T) are often auto-merged from Excel names like "TOP BANNER" or "SLOT 1". See Slots, Assets, Zones and Asset Types (data flow).

Validation checklist ​

Before saving your wireframe:

  • [ ] All required columns present (REFRESH NAME, DATE, ACTION, ASSET TYPE, SITE LOCATION or SITE_LOCATION — both accepted)
  • [ ] Actions are valid (LAUNCH, UPDATE, REMOVE, NO_CHANGE)
  • [ ] Dates in a format Excel parses (e.g. M/D/YYYY)
  • [ ] No empty rows breaking parent-child grouping
  • [ ] IPIDs follow naming convention (see Validation and fixes)
