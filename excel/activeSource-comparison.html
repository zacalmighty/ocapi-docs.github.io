activeSource: local vs smartsheet ​

Comparison of dev-env/.ocapi-config.json → workspace.activeSource for make pull and make pull CONVERT=1.

Smartsheet flow: Fetch raw Excel → compare headers to CONVERTED required keys → if match, parse directly; else run convert-excel, overwrite data/excel/LOFT (Converted).xlsx, then parse. CONVERT=1 forces convert (skips header check).

activeSource: local ​

CommandWhat happens
make pullReads data/excel/LOFT (Converted).xlsx (or Ann equivalent) from disk. No network. Parses and writes refresh JSONs to dev-env/loft/refreshes/.
make pull CONVERT=1Same as above. CONVERT=1 is only used when activeSource is smartsheet; with local it is ignored.
  • Use when: You work from the local “converted” Excel file (e.g. after downloading from Smartsheet once, or editing it by hand).
  • Requires: Nothing beyond the file at workspace.sources.local.path (default data/excel/LOFT (Converted).xlsx).

activeSource: smartsheet ​

CommandWhat happens
make pullFetches from Smartsheet → header check: if sheet has REFRESH_NAME, REFRESH_DATE, ACTION, ASSET_TYPE, SITE_LOCATION → parse directly. Else → convert to data/excel/LOFT (Converted).xlsx → parse.
make pull CONVERT=1Fetches from Smartsheet → always convert (skip header check) → overwrites data/excel/LOFT (Converted).xlsx → parse. Use when you want to save the converted file even if headers match.
  • Use when: You want the app to use live data from Smartsheet (either parse-only from temp file, or download and overwrite the converted file).
  • Requires:
    • SMARTSHEET_API_KEY in environment (or in .env; CLI loads it via dotenv).
    • Sheet ID: env var SMARTSHEET_SHEET_ID_LOFT / SMARTSHEET_SHEET_ID_ANN (brand is passed from CLI so the correct env var is used).
  • Caching: Downloads are cached for 15 minutes by default (configurable via cacheTtlMinutes). Use NO_CACHE=1 to force refresh.

Why the app can parse Smartsheet already (no convert required) ​

The app parses the raw Smartsheet Excel export (e.g. the temp file from make pull with activeSource: smartsheet) without running convert-excel. That works because:

  1. Same file format — The Smartsheet source requests Accept: application/vnd.ms-excel, so the API returns a real .xlsx. The same Excel parser and pipeline are used for local files and Smartsheet downloads.

  2. Excel config (header aliases) — src/config/excel.config.js defines HEADER_ALIASES: each canonical field (e.g. REFRESH_NAME, REFRESH_DATE, DEVICE, ASSET_TYPE) is mapped to a list of accepted column names. Smartsheet-style names are included, e.g.:

    • DEVICE ← "BANNER LABEL", "DATE/TIME", "CHANGEOUT LABEL"
    • REFRESH_NAME ← "REFRESH NAME", "PROJECT SUMMARY", "INITIATIVE NAME"
    • REFRESH_DATE ← "CHANGEOUT DATE", "LIVE DATE", "GO LIVE" So whatever column headers Smartsheet exports, the parser can resolve them to the canonical fields.

  3. Parser behavior — ExcelParser scans the first 40 rows to find the header row (the row with the most matches to the alias lookup), then builds a column map and detects sheet kind (CONVERTED, BANNER, or FLAT_TIMED). Banner/generic parsing already allows blank WEB_PROD_CODED, label from DEVICE or REFRESH_NAME, and ASSET_TYPE variants (e.g. CAROUSEL). So the structure and content of the Smartsheet export fit the same model.

CONVERT=1 is therefore optional: it downloads from Smartsheet and overwrites data/excel/LOFT (Converted).xlsx with a normalized 20-column layout (same columns every time, reordered). Parsing works either from that normalized file or directly from the raw download.
