Asset ID Rules ​

Every content asset in SFCC needs a unique, deterministic ID. This page documents how IDs are generated, the naming convention, and edge cases.

ID Formats ​

Campaign ID ​

{brand}-{date}-{refreshId}
1
ComponentSourceExample
brandConfig brand IDloft, ann
dateRefresh date (YYYY-MM-DD)2026-02-08
refreshIdOrdinal within dater1, r2, r3

Example: loft-2026-02-08-r1

Single-Zone Asset ID ​

For asset types with one zone (PPH, POPUP, COUPONS, HDR):

{brand}-{date}-{refreshId}-{assetType}
1

Example: loft-2026-02-08-r1-pph

Multi-Zone Asset ID ​

For asset types with multiple zones (HOMEPAGE):

{brand}-{date}-{refreshId}-{assetType}-{zone}
1

Example: loft-2026-02-08-r1-homepage-hp-hero

Combined Asset ID ​

When composing multi-zone types into a single OCAPI content asset, the zone suffix is stripped:

{brand}-{date}-{refreshId}-{assetType}
1

Example: loft-2026-02-08-r1-homepage (all zones composed into one asset body)

Slugification ​

Asset types and zone keys are converted to URL-safe slugs:

RuleExample
LowercasePPH → pph
Spaces → hyphensPLP HEADER → plp-header
Underscores → hyphensHP_HERO → hp-hero
Strip special charsSLOT 1: → slot-1

File Naming Convention ​

Template Files ​

Template files use the zone shorthand as the filename:

AssetTemplate Path
Homepage Heropreview/templates/homepage/hp-hero.html
Homepage Mobile Catspreview/templates/homepage/hp-mobile-cats.html
PPH (single-zone)preview/templates/pph/pph.html
Popup (single-zone)preview/templates/popup/popup.html

The full SFCC asset ID appears in the Handlebars comment at the top:

handlebars
{{!--
  @asset: loft-2026-02-08-r1-homepage-hp-hero
  @data-source: assets/homepage.json
  @zone: HP_HERO
  @items: 1
--}}
1
2
3
4
5
6

Rendered Files ​

Composed output files use the asset type as the filename:

FileContents
preview/rendered/homepage.htmlAll homepage zones composed
preview/rendered/pph.htmlSingle-zone PPH
preview/rendered/popup.htmlSingle-zone Popup

Each starts with an asset identification comment:

html
<!-- asset: loft-2026-02-08-r1-homepage | type: HOMEPAGE | zones: 11 -->
1

ID Parsing ​

The system can parse an asset ID back into its components:

javascript
parseRefreshAssetId("loft-2026-02-08-r1-homepage-hp-hero")
// → { brand: "loft", date: "2026-02-08", refreshId: "r1",
//     assetType: "homepage", zone: "hp-hero" }
1
2
3

This is used for:

  • Determining which template directory to save to
  • Looking up zone templates during composition
  • Building preview file paths
  • Registry operations

Edge Cases ​

Missing Date ​

If the date can't be determined, falls back to "unknown-date".

Missing Refresh ID ​

If the refresh ordinal can't be determined, defaults to "r1".

Zone-less Multi-Zone Type ​

If a multi-zone type (HOMEPAGE) has only one zone, the ID still includes the zone:

loft-2026-02-08-r1-homepage-hp-hero   ← still zone-qualified
1

Ann Taylor PPH Slots ​

Ann Taylor has multiple PPH slots (SLOT 1-5). Each gets its own asset ID:

ann-2026-02-08-r1-pph-slot-1
ann-2026-02-08-r1-pph-slot-2
1
