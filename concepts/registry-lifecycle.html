Registry Lifecycle ​

The Asset Registry is a per-brand JSON file that tracks what's currently live in SFCC. It's the source of truth for deciding whether to create new assets or reuse existing ones.

Location ​

dev-env/loft/asset-registry.json
dev-env/ann/asset-registry.json
1
2

Purpose ​

The registry answers three questions:

  1. What asset ID is live for a given zone? (for UPDATE/NO_CHANGE reuse)
  2. When was it launched? (for audit trail)
  3. What zones exist? (for homepage carry-forward composition)

Registry Entry Structure ​

json
{
  "HOMEPAGE": {
    "HP_HERO": {
      "currentAssetId": "loft-2026-02-08-r1-homepage-hp-hero",
      "launchedAt": "2026-02-08",
      "refreshId": "r1",
      "lastUpdated": "2026-02-08T15:30:00.000Z",
      "items": [
        { "order": 1, "action": "LAUNCH", "copy": "Spring Sale..." }
      ]
    },
    "HP_TOP_BANNER": {
      "currentAssetId": "loft-2026-02-05-r1-homepage-hp-top-banner",
      "launchedAt": "2026-02-05",
      "refreshId": "r1",
      "lastUpdated": "2026-02-05T10:00:00.000Z"
    }
  },
  "PPH": {
    "PPH": {
      "currentAssetId": "loft-2026-02-08-r1-pph",
      "launchedAt": "2026-02-08",
      "refreshId": "r1"
    }
  }
}

Operations ​

Register (LAUNCH) ​

Triggers: LAUNCH action, or auto-bootstrap (first run when no entry exists)

Reuse (UPDATE / SKIP / NO_CHANGE) ​

When a zone has UPDATE, SKIP, or NO_CHANGE, the existing asset ID is returned:

Carry-Forward for Composition ​

When composing the homepage, the registry is checked for zones not present in the current refresh:

This ensures the composed homepage is always complete, even when only a few zones change.

How Previous HTML Is Found ​

  1. Registry provides the currentAssetId and refreshId for the zone
  2. System looks in dev-env/{brand}/refreshes/{date}/{refreshId}/preview/templates/{type}/{zone}.html
  3. Falls back to legacy path with full asset ID filename if short name not found
