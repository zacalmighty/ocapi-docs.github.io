Slots, Assets, Zones ​

This page explains how promotional content maps from wireframe concepts to SFCC structures.

The Hierarchy ​

Content Assets ​

A ContentAsset is an HTML fragment stored in SFCC's content library. It's the atomic unit of promotional content.

Properties ​

PropertyDescription
idUnique asset identifier
nameDisplay name in Business Manager
c_bodyOCAPI-formatted body (escaped HTML)
contentSanitized HTML content

Example ​

javascript
ContentAsset {
  id: "loft-2026-02-03-r1-homepage-hp-hero",
  name: "LOFT HP Hero - Feb 3",
  content: "<div class='promo-banner'>...</div>",
  c_body: { default: "<div class='promo-banner'>...</div>" }
}

Slot Configurations ​

A SlotConfiguration binds a ContentAsset to a specific page slot within a Campaign.

Properties ​

PropertyDescription
slot_idSFCC slot ID (e.g., "global-promotion-banner")
configuration_idUnique config ID for OCAPI
context"global" or "category"
context_idCategory ID (for category-scoped slots)
assetThe ContentAsset to display
start_date / end_dateActivation schedule
syncStrategyHow this slot syncs: content-slot, plp-callout, etc.

Context Types ​

ContextDescriptionExample
globalSame content site-wideHomepage banner, PPH
categoryContent scoped to a categoryPLP header, Coupons

Category Slot Fanout ​

For category-scoped slots, siteLocation may contain multiple category IDs (newline-separated). The system "fans out" a single asset into one slot binding per category:

siteLocation: "cat4460023\ncat3070015\ncatl00009"

→ Slot binding 1: context="category", context_id="cat4460023"
→ Slot binding 2: context="category", context_id="cat3070015"
→ Slot binding 3: context="category", context_id="catl00009"

Zones ​

A Zone is a wireframe concept representing a specific content area within an asset type. Zones are stored as ordered arrays preserving the original sequence from the Excel source.

Zone Data Format ​

Zones use canonical HP_ prefixed names and are stored as ordered arrays:

json
{
  "assetType": "HOMEPAGE",
  "zones": [
    { "zone": "HP_MOBILE_CATS", "items": [
      { "order": 1, "action": "SKIP", "copy": "NEW ARRIVALS", "device": "BOTH", "destination": { "type": "CATEGORY", "id": "catl00009" } },
      { "order": 2, "action": "SKIP", "copy": "SALE", "device": "BOTH", "destination": { "type": "CATEGORY", "id": "catl000065" } }
    ]},
    { "zone": "HP_HERO", "items": [{ "order": 1, "action": "LAUNCH", "copy": "...", "device": "BOTH" }] },
    { "zone": "HP_2T", "items": [{ "order": 1, "action": "SKIP", "copy": "...", "device": "BOTH" }] }
  ]
}

Normalization

All actions, devices, and site locations are normalized at parse time. For example, NO CHANGE/LINK SAME becomes SKIP, RESPONSIVE D & M becomes BOTH, and POP UP becomes POPUP. This ensures both Converted and Changeouts Excel formats produce identical data structures.

Homepage Zone Consolidation ​

Standalone Excel asset types like "CAT A", "SLOT 1:", "BOTTOM BANNER" are automatically consolidated into HOMEPAGE zones during parsing via the HOMEPAGE_ZONE_MAP in slots.config.js. For example:

  • "HP CAT NAV" (standardized from CAT A–K in Excel) → merged as items into HP_MOBILE_CATS
  • "SLOT 1" through "SLOT 4" → merged into HP_SLOTS
  • "CAT IMAGE" (standardized from CAT A–F IMAGE in Excel) → merged into HP_CAT_IMAGE
  • "BOTTOM BANNER" → merged into HP_BOTTOM_BANNER

This ensures the homepage is always one consolidated asset with all zones, regardless of how the Excel structures the data.

Zone Composition ​

For multi-zone asset types like Homepage, the ComposePreview use case combines individual zone templates into a single preview.

Configuration ​

Asset type configuration is defined in slots.config.js:

javascript
PPH: {
  active: true,
  mode: 'TEMPLATE',
  syncStrategy: 'content-slot',
  slot: { id: 'global-promotion-banner', context: 'global' },
  template: 'pph/template',
}
