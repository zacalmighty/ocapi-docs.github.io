Overview ​

Campaign content automation for LOFT and Ann Taylor websites. Pulls data from Smartsheet or Excel, generates HTML, validates, and syncs to SFCC.

How It Works ​

Pull → Build → Push → Replicate → Done
1
StepCommandDescription
1make pullGit sync + fetch data from Smartsheet/Excel
2make buildGenerate HTML from templates (guarded — skips if already built)
3make pushValidate data quality + sync to SFCC staging
4make replicateManual STG → POD replication checklist
5make doneGenerate changeout email + commit hint

Quick start:

bash
make setup                     # First time — configure brand
make pull                      # Git sync + fetch + dashboard
make build                     # Build the selected date
make push                      # Validate + sync to staging
make done                      # Email + save work

Asset Modes ​

ModeBehavior
TEMPLATERegenerated from master templates (PPH, Popup)
DEVELOPERPreserved across generations (Homepage zones)

Custom HTML edits in DEVELOPER mode are preserved across fetches.

Two-App Architecture ​

AppAudiencePurpose
Producer CLIWeb producers (4 people, 2 per brand)Daily workflow: pull, build, push, done
Dev CLIWeb developerConfigs, registry, templates, testing, demo

Producers share work via Git. Each producer has a personal "sticky date" (make select) so they never need to type DATE= on every command.

Multi-Producer Workflow ​

Two producers per brand coordinate via Git:

  1. Each runs make pull to sync with the team
  2. Each selects a different date with make select
  3. Build guards prevent accidentally overwriting another producer's synced work
  4. make commit saves finished work for the team

See Multi-Producer Guide for details.
