Internal Onboarding ​

Canonical onboarding guide for internal CLI rollout. Use this as the source of truth for access, setup, verification, and escalation.

Day 0 Access Checklist ​

Before first run, confirm all required access:

AreaRequired accessOwner / approver
RepoRead/write access to this repositoryEngineering lead
SFCCBusiness Manager + OCAPI client scope permissionsSFCC admin
Data sourceSmartsheet access (if using Smartsheet mode)Marketing ops
RuntimeNode.js 18+ and npm on local machineDeveloper workstation owner

If any access is missing, stop here and request access before setup.

Local Setup ​

bash
npm install
make status
1
2

make status is the single entry point:

  1. Runs setup automatically if config is missing
  2. Opens the status hub after setup
  3. Lets you choose active refresh/date

Required Secrets and Local Files ​

  • Keep credentials only in local .env / .env.* files.
  • Never commit credentials, token cache, or local config state.
  • dev-env/.ocapi-config.json and dev-env/.token-cache.json are local runtime artifacts.

For full environment variable details, see Environment Setup.

First-Run Verification ​

Run this sequence and confirm each step succeeds:

bash
make status
make pull
make refresh
make reports OP=report DATE=YYYY-MM-DD
1
2
3
4

Expected outcome:

  • You can select a refresh in status
  • Pull fetches/parses data without fatal errors
  • Refresh builds preview/templates
  • Reports render zone/IPID output for the selected date

Escalation Path ​

If blocked, escalate in this order:

  1. Workflow owner: producer lead for process questions
  2. Engineering owner: CLI maintainers for command/runtime failures
  3. SFCC owner: platform admin for auth/scope/SFCC-side issues

When escalating, include:

  • Command run
  • Full error message
  • Brand/date/refresh context
  • Whether issue reproduces after make pull
