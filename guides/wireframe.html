Wireframe Guide ​

How to structure Excel/Smartsheet wireframes for the SFCC Campaign Automation system.

Overview ​

The wireframe is the source of truth for all campaign content. This guide explains the required format and structure.

Supported Excel Formats ​

The system auto-detects the format based on column headers:

FormatWhen to UseDetection
CONVERTEDStandard format (recommended)Has REFRESH_NAME, REFRESH_DATE, ACTION, ASSET_TYPE, SITE_LOCATION
BANNERLegacy LOFT formatHas WEB_PROD_CODED, DEVICE with date patterns
FLAT_TIMEDTimed refreshesHas REFRESH_DATE, START_DATETIME, ACTION

IPID Format ​

IPIDs (Internal Promotion IDs) are used for analytics tracking.

Structure ​

This structure is the canonical definition. The system builds every IPID from exactly these eight segments, in order:

{brand}_{page}_{device}_{zone}_{position}_{promo}_{destination}_{date}
1

Segment reference (canonical) ​

SegmentPlaceholderDescriptionExample values
1. Brand{brand}Brand key (no cross-brand)loft, at
2. Page{page}Page / asset typehp, pph, popup, plp
3. Device{device}Device / audienceall, mobile, desktop
4. Zone{zone}Zone within the pagehero1ta1, main, hp-2t
5. Position{position}Item position in zone (1-based)1, 2, a
6. Promo{promo}Promo/copy slug or npsale50, 30offsuiting, np
7. Destination{destination}Destination slugsaleviewall, suits, na
8. Date{date}MMDDYY (6 digits only)012626, 012026
  • Date segment: Exactly MMDDYY (6 digits). No other date format is used for IPIDs.
  • Brand segment: loft or at only. No cross-brand use: LOFT assets must use only loft_ IPIDs; Ann Taylor assets must use only at_ IPIDs.

Examples ​

IPIDBreakdown
loft_hp_all_hero1ta1_sale50_saleviewall_012626LOFT, homepage, all audiences, hero zone, 50% sale, Jan 26 (MMDDYY: 012626)
at_pph_all_pph_1_30offsuiting_suits_012026Ann Taylor, PPH, all, 30% off suiting, Jan 20 2026 (MMDDYY: 012026)

Best Practices ​

  • Lowercase only
  • Underscores as separators
  • Date at end: MMDDYY only (6 digits)
  • No cross-brand: Use the correct brand prefix for the current run
  • Be consistent across refreshes

Multiple Refreshes Per Day ​

If you have multiple refreshes on the same day:

  1. Include time in the refresh name: "1/26 3AM Site Changeout"
  2. The system assigns ordinals automatically: r1, r2, r3...
  3. Use the TIME column for precise scheduling

Multiple Sheets ​

The system scans all sheets in the workbook and uses the first one that matches a known format.

Priority order: CONVERTED > BANNER > FLAT_TIMED

To force a specific sheet, run: make excel ARGS="--sheet='Sheet Name'"

Validation Checklist ​

Before saving your wireframe:

  • [ ] All required columns present (REFRESH NAME, DATE, ACTION, ASSET TYPE, SITE LOCATION)
  • [ ] Actions are valid (LAUNCH, NO_CHANGE, REMOVE)
  • [ ] Dates are in M/D/YYYY format
  • [ ] No empty rows breaking parent-child grouping
  • [ ] IPIDs follow naming convention
  • [ ] Zones match expected values for each asset type

Common Issues ​

Issue: Rows not parsing ​

Check:

  • Is there a parent row with REFRESH NAME and DATE?
  • Are required columns present?
  • Are there merged cells breaking the structure?

Issue: Wrong asset type ​

Check:

  • Is ASSET TYPE spelled correctly?
  • Is SITE LOCATION filled in?
  • Does the zone name match expected patterns?

Issue: Dates not recognized ​

Check:

  • Use M/D/YYYY format (1/26/2026)
  • Avoid text formatting on date cells
  • Check Excel is interpreting as date, not text
