Environment Setup ​

Complete guide to configuring your environment for SFCC Campaign Automation.

Prerequisites ​

Before starting, ensure you have:

  • Node.js 18 or higher
  • npm 9 or higher
  • Access to SFCC Business Manager (for OCAPI credentials)
  • Git (for cloning the repository)

Verify your Node.js version:

bash
node --version
# v18.x.x or higher

npm --version
# 9.x.x or higher

Installation ​

1. Clone the Repository ​

bash
git clone <repository-url>
cd loft-ocapi

2. Install Dependencies ​

bash
npm install

3. Run Setup Wizard ​

bash
make setup

This creates dev-env/.ocapi-config.json with your preferences.

Obtaining OCAPI Credentials ​

Step 1: Access Business Manager ​

  1. Log in to SFCC Business Manager
  2. Navigate to Administration → Site Development → Open Commerce API Settings

Step 2: Create API Client ​

  1. Go to API Client section
  2. Click Create New API Client
  3. Fill in details:
    • Client ID: Auto-generated or custom
    • Display Name: "Campaign Automation"
    • Allowed Scopes: (see below)

Step 3: Configure Scopes ​

Required OCAPI scopes:

- /campaigns/* (read/write)
- /content/* (read/write)
- /libraries/* (read/write)
- /slot_configurations/* (read/write)
1
2
3
4

Step 4: Get Client Secret ​

  1. After creating the client, note the Client Secret
  2. This is shown only once — save it securely

WARNING

Never commit your .env file to version control. It's already in .gitignore.

If each brand requires different SFCC credentials, maintain separate .env sections and switch the SFCC_SITE_ID and SFCC_LIBRARY_ID values.

Troubleshooting ​

"Missing environment variables" ​

Ensure all required variables are in .env:

bash
# Check which variables are set
grep SFCC .env
1
2

"Connection timeout" ​

  1. Check VPN connection
  2. Verify SFCC_BASE_URL is correct
  3. Test with curl:
    bash
    curl -I $SFCC_BASE_URL
    1

"401 Unauthorized" ​

  1. Verify SFCC_CLIENT_ID and SFCC_CLIENT_SECRET
  2. Check if credentials have expired
  3. Verify OCAPI scopes are configured correctly

Security Best Practices ​

  1. Never commit .env — It's in .gitignore
  2. Rotate secrets regularly — Update credentials periodically
  3. Use least-privilege scopes — Only grant necessary permissions
  4. Audit access — Review who has credentials
