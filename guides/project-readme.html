SFCC Campaign Automation ​

Manages LOFT and Ann Taylor site refreshes. Fetches data from Smartsheet/Excel, generates HTML from Handlebars templates, syncs to SFCC via OCAPI.

New to this tool? Start with Internal Onboarding, then use the Quick-Start Guide.

Producer Quickstart ​

Use make as the primary interface. Start with the status hub and run actions from there.

bash
npm install
make setup
make status

Commands ​

Full list: make help (producer) and make dev (developer). See Commands Reference. Per-command options: make <command> ARGS="--help". The Makefile is the source of commands; direct node src/cli/index.js is for debugging and scripting only.

Producer ​

CommandDescription
make pullGit sync + fetch data + auto-build new dates
make refreshBuild selected refresh (generate dev files + payload)
make pushValidate + sync to SFCC staging
make statusDashboard — view all refreshes, switch dates. Add ALL=1 for full history. In a TTY you get the interactive picker; in non-TTY (e.g. CI or pipe) or with ARGS="--no-interactive" you get the table only.
make uploadPartial asset sync (hotfix)
make delete DATE=Remove refresh from SFCC + local
make reportsVisibility reports (OP=report, OP=history, OP=coverage)

Dev ​

CommandDescription
make setupConfiguration wizard (brand, data source, OCAPI)
make switch [BRAND=]Toggle brand (no arg) or switch to specific (e.g. make switch BRAND=ann)
make doctorValidate setup, config, and environment
make build-allBuild every date for current brand (CI/batch; FAIL_FAST=1 to stop on error)
make push-allSync every date to SFCC (YES=1 to skip prompts; FAIL_FAST=1 to stop on error)

Make Variables ​

VariableEffectExample
YES=1Skip confirmation/approval promptsmake push YES=1
FORCE=1Force rebuild or re-push (bypass approval guard); skip delete confirmationmake push FORCE=1; make delete DATE=… FORCE=1
ALL=1refresh/push: all refreshes in a date; status: full historymake status ALL=1
FAIL_FAST=1Stop build-all/push-all on first failuremake build-all FAIL_FAST=1
ARGS="..."Pass extra CLI flagsmake push ARGS="--yes --force"

Use --yes (or YES=1 with make) to skip confirmation prompts in non-interactive or CI runs (e.g. when data quality has warnings).

Architecture ​

Clean Architecture with explicit dependency direction:

CLI → Application (use cases + ports) → Domain (entities + validation)
                  ↑
        BrandContext (composition root) → Infrastructure (SFCC, filesystem, rendering, payload)
1
2
3
  • Domain — Pure business entities (Campaign, ContentAsset, SlotConfiguration), validation (Zod schemas). No I/O.
  • Application — Use cases orchestrate domain + ports. No direct infrastructure imports (only via BrandContext).
  • Infrastructure — SFCC OCAPI client, filesystem store, Excel parsing, HTML rendering, payload building.
  • CLI — Thin command adapters using shared middleware for refresh resolution, dry-run gating, and OCAPI guards.

Dependency Pins (CJS Compatibility) ​

This project is CommonJS ("type": "commonjs" in package.json). The following packages are pinned to their last CJS-compatible major version. Newer majors are ESM-only and will break require() calls throughout the codebase.

PackagePinnedESM-only starts atWhy pinned
chalk^4.xv5sindresorhus ESM migration
strip-ansi^6.xv7sindresorhus ESM migration
clipboardy^2.xv3sindresorhus ESM migration

Do not run npm install <package>@latest for these. If you need to upgrade past these majors, the entire project must first migrate to ESM ("type": "module", convert all require()/module.exports to import/export).

Security ​

  • Never commit .env — it is git-ignored. If it was ever committed, rotate all secrets immediately.
  • Run npm run audit (or make check) before release. High-severity issues are mitigated via npm overrides (see SECURITY.md).
  • See SECURITY.md for vulnerability handling and accepted risks.
  • See Environment Setup for full security best practices.
