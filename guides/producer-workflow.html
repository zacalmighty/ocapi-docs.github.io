Producer Guide ​

One guide for web producers: daily workflow, guards, and (optional) assessment for 4 producers (2 per brand).

Use this sectionWhen
Daily workflow (below)Your main reference: pull → preview → push → commit. (make push auto-generates email)
Quick StartFirst-time setup: install, then make status (runs setup if no config).
Multi-ProducerWorking with a partner on the same brand (2 per brand).
Ecomm (Smartsheet)Smartsheet/ecomm workflow and data flow.
Assessment for 4 producersOptional: fit, gaps, and recommendations for teams moving from manual.

Start with Quick Start, then use the daily workflow below. If you share a brand with another producer, see Multi-Producer. For Smartsheet/ecomm, see Ecomm (Smartsheet).

Principle: Use Make Only ​

You do not need to run node directly. All producer commands are:

bash
make <command>
1

make help shows the full list. If a developer asks you to run a Node script, ask them to expose it via make instead.

Overview ​

Wireframe → build → preview → push to staging. The changeout email is generated automatically.

Entry point: make status is the main entry point. On first run with no configuration, it runs setup (view/edit config), then continues to the dashboard. it’s your dashboard. It shows what’s live, synced, ready to push, or needs a build. When the wireframe has start and end times, status shows which refresh is on the homepage right now (Current live) and displays time ranges on each row so you can see which refresh covers which period. Picking a refresh from the status picker sets it as your active refresh, then you choose an action (preview, push, etc.) from the same screen.

Core flow:

make pull  →  make preview  →  make push  →  make replicate  →  make commit
1

make preview auto-builds if data is stale (shows diff + approval prompt). make push auto-generates the changeout email (copied to clipboard) and points to make replicate as the next step.

You don't need to change configs or templates in normal use—the developer manages those. You don't need to type dates or refresh numbers: after make pull you pick your working date once; the app remembers it for make preview, make push, and the rest. Flags like DATE= or REFRESH= are for testing and automation, not daily use.

Starting Your Day ​

Step 1: Status or Pull ​

bash
make status
1

or

bash
make pull
1

make status is the single entry point: if you have no config, it runs setup first, then opens the hub. make pull is an alternative that fetches data and auto-builds, then opens the same status hub. Pull does four things:

  1. Git pull — syncs your local files with the rest of the team
  2. Fetch — parses the latest Excel/Smartsheet into refresh data (progress: "Fetching data … Parsing {file}")
  3. Auto-build — builds only dates that don't have a build yet (progress: "Building new dates …" or "All dates already built")
  4. Status hub — opens the status dashboard

Use arrow keys to move, Enter to select a refresh. That becomes your sticky working date for all following commands. From the same screen you can run an action (Browse files, Push, etc.) or press q to exit.

Producer thinking & blocking errors

After pull: "Got the data. Now I'll pick the date I'm working on."

Blocking error (no Smartsheet config):

  ❌ Failed to fetch from smartsheet: Smartsheet sheet ID not configured.
  Set SMARTSHEET_SHEET_ID_LOFT env var or add sheetId to config.
1
2

Fix: Run make setup and configure Smartsheet, or switch to local via the setup wizard.

What if it says "Already built"? ​

  ✔  Already built.
     make push            (push as-is)
     make build FORCE=1   (rebuild)
1
2
3

This is a build guard — it prevents you from accidentally regenerating work that's ready to push. If you need to rebuild, use make build FORCE=1.

What if it says "Already synced"? ​

  ⚠  Already synced. Choose a different refresh or rebuild:
     make status          (pick a different refresh)
     make build FORCE=1   (force rebuild)
1
2
3

Someone (maybe you, maybe your partner) already pushed this date to SFCC. You don't need to rebuild it. Pick a different date.

Switching Dates ​

Via status (preferred) ​

bash
make status
1

Pick a different refresh from the dashboard — use arrow keys to navigate, Enter to select. That selection becomes your active refresh, then choose an action (preview, push, etc.).

Direct set ​

bash
make status DATE=2026-02-14
1
  ✔ Selected 2026-02-14 (Valentine's Day)
  Status: · NEW — needs make build
1
2

Override for one command ​

Any command accepts DATE= to override the sticky selection without changing it:

bash
make preview DATE=2026-02-10    # Preview 02/10 without switching
1

Switching Data Source ​

To switch between local Excel and Smartsheet:

bash
make setup
1

Choose Edit configuration and select your data source. Next make pull will fetch from the new source. Switching to Smartsheet requires SMARTSHEET_API_KEY in .env (your developer sets this up). To switch back to local, run make setup again and choose Local Excel file.

Switching OCAPI (SFCC Sync) ​

To check whether OCAPI sync is enabled:

bash
make config
1

Shows OCAPI: enabled or disabled. To toggle: run make setup, choose Edit configuration, and toggle the OCAPI option. Pushing to SFCC requires the SFCC env vars in .env.

Force Rebuild Flow ​

After a template edit (e.g., fixing a typo in the homepage HTML):

bash
# Edit the file in dev-env/loft/refreshes/2026-02-12/r1/preview/templates/...
make build FORCE=1  # Force-rebuild (bypasses build guard)
make push          # Re-sync to staging (use make push FORCE=1 if this refresh was already synced)
make commit        # Save

Appendix: Assessment for 4 producers ​

Optional reading for leads: fit and gaps for 4 web producers (2 LOFT, 2 Ann Taylor) moving from a manual process. Daily how-to is in the sections above.

Fit: Single flow (pull → build → preview → push → commit), sticky date, build/sync guards, data quality before push, email auto-generated by push, multi-producer safety via Git. No need to touch configs/templates in normal use.

Gaps to know: (1) One brand per config—use make switch TO=... if working both. (2) Data errors fixed in Excel/Smartsheet, then make pull and retry. (3) Multiple refreshes (r1, r2): use picker or REFRESH=r2 / ALL=1. (4) make replicate is checklist only; STG → POD manual. (5) First-time: make setup, SFCC env vars, make health—see Quick Start. 2 per brand: own machine and sticky date; always make pull first, make commit + git push after push/done. Force rebuild: edit template → make build FORCE=1 → make push (use FORCE=1 if already synced).

DimensionAssessment
Fit (2 per brand)Good: sticky date, guards, Git sharing, clear flow.
Transition from manualGood: one linear flow, data quality, preview; source of truth = Excel.
