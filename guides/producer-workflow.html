Producer Guide ​

One guide for web producers: daily workflow, guards, and (optional) assessment for 4 producers (2 per brand).

Use this sectionWhen
Daily workflow (below)Your main reference: pull → build → preview → push → done → commit.
Quick StartFirst-time setup: install, make setup, first make pull.
Multi-Producer GuideWorking with a partner on the same brand (2 per brand).
Assessment for 4 producersOptional: fit, gaps, and recommendations for teams moving from manual.

Start with Quick Start, then use the daily workflow below. If you share a brand with another producer, read Multi-Producer Guide.

Overview ​

Your job: take campaign data from Smartsheet/Excel, build it into HTML, push to SFCC staging, and send the changeout email. Core flow:

make pull  →  make build  →  make push  →  make done  →  make commit
1

You never need to touch configs, templates, or the registry. That's the developer's job.

Starting Your Day ​

Step 1: Pull ​

bash
make pull
1

This is always your first command. It does three things:

  1. Git pull — syncs your local files with the rest of the team
  2. Fetch — parses the latest Excel/Smartsheet into refresh data
  3. Dashboard — shows every date and its status

Switching Dates ​

Interactive picker ​

bash
make select
1

Shows the arrow-key date browser. Navigate with up/down, Enter to select.

Direct set ​

bash
make select DATE=2026-02-14
1
  ✔ Selected 2026-02-14 (Valentine's Day)
  Status: · NEW — needs make build
1
2

Override for one command ​

Any command accepts DATE= to override the sticky selection without changing it:

bash
make preview DATE=2026-02-10    # Preview 02/10 without switching
1

Hotfix Flow ​

After a template edit (e.g., fixing a typo in the homepage HTML):

bash
# Edit the file in dev-env/loft/refreshes/2026-02-12/r1/preview/templates/...
make edit          # Force-rebuild (bypasses build guard)
make push          # Re-sync to staging
make commit        # Save

Appendix: Assessment for 4 producers ​

Optional reading for leads: assessment of the application for 4 web producers (2 LOFT, 2 Ann Taylor) who previously used a manual process. The daily how-to is in the sections above.

Who they are ​

RoleCountBrand(s)Old way
Web Producer (LOFT)2LOFTManual Excel → manual HTML/copy → manual SFCC upload or campaign setup
Web Producer (Ann Taylor)2Ann TaylorSame

Manual way (before this tool): Producers would take wireframe data (Smartsheet/Excel), build or copy content into HTML or SFCC by hand, upload assets, configure campaigns and slots in Business Manager, then send changeout emails. Error-prone, repetitive, and hard to coordinate when two people work the same brand.

Fit summary ​

The app gives them a single flow (pull → build → preview → push → done → commit), sticky date, build/sync guards, data quality checks before push, and multi-producer safety via Git. Strengths: no need to touch configs/templates, guards prevent overwriting a partner’s work.

Gaps and risks (manual → tooling) ​

  • Brand is global — One brand in config; use make switch TO=loft / TO=ann if working both. Usually each producer has their own machine and stays on one brand.
  • “Fix in Excel and re-fetch” — Data quality errors are fixed in the Excel/Smartsheet; then run make pull and try make push again. The tool enforces source of truth = Excel/Smartsheet.
  • Multiple refreshes per date (r1, r2) — Use the interactive picker or pass REFRESH=r2 (or ALL=1). See push and Commands Reference.
  • Replicate is still manual — make replicate opens a checklist for STG → POD; it does not perform replication itself.
  • First-time setup and credentials — make setup plus SFCC env vars; make health verifies. Quick Start has the checklist.

For the 4 producers ​

  • 2 per brand: Each producer runs on their own machine, sticky date is personal, build/sync guards protect the other. Always make pull first and make commit + git push after push/done.
  • If someone covers both brands: Use make switch TO=... and run make status to confirm brand before building/pushing.
  • Manual legacy: They no longer hand-edit HTML for standard flows; the tool generates and syncs. Hotfix: edit template → make edit → make push (and optionally FORCE=1 if already synced).

Summary ​

DimensionAssessment
Fit for 4 producers (2 per brand)Good: sticky date, guards, Git-based sharing, clear flow.
Transition from manualGood: one linear flow, data quality before SFCC, preview; need clear “source of truth = Excel” and first-day setup.
Brand switchingDocumented; matters only if one person works both brands.
Multi-refresh datesHandled via sticky + picker or REFRESH= / ALL=1.
Replicate / productionBy design manual; docs state it.
