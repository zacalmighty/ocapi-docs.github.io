Smartsheet Fetch Guide ​

How to configure and use Smartsheet as a data source for campaign automation.

Overview ​

The Smartsheet integration supports:

  • Brand-specific sheet IDs from environment variables
  • Simulation mode when API key is missing (for testing)
  • Automatic fallback to env vars when sheet ID not in config

Configuration ​

Option 1: Environment Variables (Recommended) ​

Set brand-specific sheet IDs in your .env file:

bash
# API key (required for real API calls)
SMARTSHEET_API_KEY=your-api-key-here

# Brand-specific sheet IDs
SMARTSHEET_SHEET_ID_LOFT=1234567890123456
SMARTSHEET_SHEET_ID_ANN=9876543210987654

The system automatically uses the correct sheet ID based on the brand:

  • make pull BRAND=loft → Uses SMARTSHEET_SHEET_ID_LOFT
  • make pull BRAND=ann → Uses SMARTSHEET_SHEET_ID_ANN

Option 2: Config File ​

Alternatively, configure in dev-env/.ocapi-config.json:

json
{
  "brand": "loft",
  "activeSource": "smartsheet",
  "sources": {
    "smartsheet": {
      "sheetId": "1234567890123456"
    }
  }
}

Save Converted File to docs/excel (golden format) ​

When using Smartsheet, you can fetch and run the sheet through the same convert-excel pipeline used for local raw files. The converted file is saved next to your local examples so you can diff, commit, or use it as the local source:

bash
make pull CONVERT=1
1
  • Fetches from Smartsheet → writes raw to a temp file (OS temp dir; not cached).
  • Runs scripts/convert-excel.js → writes docs/excel/LOFT (Converted) - Smartsheet.xlsx (or Ann (Converted) - Smartsheet.xlsx for Ann).
  • Parses from that file and persists refresh files as usual.

The only artifact you keep is the file in docs/excel/.

With Local File Override ​

bash
# Override with local Excel file
make pull BRAND=loft FILE=docs/excel/LOFT.xlsx

Simulation Mode ​

If SMARTSHEET_API_KEY is not set, the system automatically runs in simulation mode:

bash
# Without API key - generates placeholder file
make pull BRAND=loft
# Output: ⚠️  Simulation mode: No API key found. Generating placeholder file.
1
2
3

What simulation mode does:

  • Generates a minimal Excel file with placeholder data
  • Uses the configured sheet ID (from env var or config)
  • Writes to a temp file (OS temp dir) for the current run
  • Allows testing the workflow without API access

When to use simulation mode:

  • Testing the workflow locally
  • Development without Smartsheet access
  • CI/CD pipelines where API key isn't available
  • Demonstrating the system to stakeholders

How It Works ​

1. Sheet ID Resolution ​

The system resolves sheet IDs in this order:

  1. Config file (dev-env/.ocapi-config.json → sources.smartsheet.sheetId)
  2. Environment variable (SMARTSHEET_SHEET_ID_{BRAND})
  3. Error if neither is found

2. API Key Check ​

  • Present: Makes real API call to Smartsheet
  • Missing: Runs in simulation mode (generates placeholder)

3. Fetch Process ​

Real API Call:

1. Check API key → Found
2. Check sheet ID → Found (from env or config)
3. Make HTTPS request to api.smartsheet.com
4. Download sheet as Excel to OS temp dir (loft-ocapi-smartsheet-{sheetId}.xlsx)
5. Return path for parsing

Troubleshooting ​

Error: "Smartsheet sheet ID not configured" ​

Solution: Set the sheet ID either:

  • In .env: SMARTSHEET_SHEET_ID_LOFT=your-id
  • In config: dev-env/.ocapi-config.json → sources.smartsheet.sheetId

Error: "Smartsheet API authentication failed" ​

Solution: Check your API key:

bash
echo $SMARTSHEET_API_KEY  # Should show your key
1

Simulation Mode When You Want Real Data ​

Solution: Set the API key:

bash
export SMARTSHEET_API_KEY=your-key
make pull BRAND=loft
1
2

Best Practices ​

  1. Use environment variables for sheet IDs (easier to manage per brand)
  2. Keep API key in .env (never commit to git)
  3. Use simulation mode for local development/testing
  4. Set sheet IDs per brand in env vars for clarity
  5. Test with simulation before using real API calls

Related Commands ​
