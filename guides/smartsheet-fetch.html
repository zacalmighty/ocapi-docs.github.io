Smartsheet Fetch Guide ​

How to configure and use Smartsheet as a data source for campaign automation.

Overview ​

The Smartsheet integration supports:

  • Brand-specific sheet IDs from environment variables
  • Automatic caching (15-minute TTL by default)
  • Simulation mode when API key is missing (for testing)

Configuration ​

Environment Variables (Required) ​

Set brand-specific sheet IDs and API key in your .env file:

bash
# API key (required for real API calls)
SMARTSHEET_API_KEY=your-api-key-here

# Brand-specific sheet IDs
SMARTSHEET_SHEET_ID_LOFT=1234567890123456
SMARTSHEET_SHEET_ID_ANN=9876543210987654

Header-based auto-detect ​

When make pull runs with Smartsheet, the app:

  1. Fetches raw Excel from the API.
  2. Compares headers to CONVERTED required keys (REFRESH_NAME, REFRESH_DATE, ACTION, ASSET_TYPE, SITE_LOCATION).
  3. If all match → parses directly (no convert).
  4. If not → runs scripts/convert-excel.js → overwrites data/excel/LOFT (Converted).xlsx (or Ann) → parses that file.

Schedule and date/time columns ​

Smartsheet (or any source Excel) can provide campaign windows in either form:

  1. Schedule (or “Date Range”) column — A single column with a range string in SFCC-style format, e.g. 1/7/2026 3:00:00 pm to 1/8/2026 3:00:00 am. Supported header aliases include: Schedule, Date Range, Campaign Schedule, Start to End (and their lowercase variants).
  2. Separate Start and End columns — START_DATETIME and END_DATETIME (or aliases) with values like 1/8/2026 3:00:00 am.

The app uses these values as entered (interpreted in local time) and shows the correct window in status, including next-day end times (e.g. 3 pm to 3 am). Defaults (19:00 start / 23:59 end same day) apply only when the source does not provide start or end.

Force convert and save to data/excel ​

To always run convert and overwrite the local converted file (skip header check):

bash
make pull CONVERT=1
1
  • Fetches from Smartsheet → runs scripts/convert-excel.js → overwrites data/excel/LOFT (Converted).xlsx (or Ann).
  • Parses from that file and persists refresh files as usual.

Use when you want to save the normalized 20-column layout even if headers already match.

Caching ​

Smartsheet downloads are cached locally to avoid redundant API calls during rapid iteration.

Cache Behavior ​

ScenarioBehavior
First fetchDownloads from API, saves to data/smartsheet/{brand}-latest.xlsx
Subsequent fetch (< TTL)Uses cached file, logs: 📥 Using cached Smartsheet (X min old, TTL: 15 min)
Cache expired (> TTL)Re-downloads from API
NO_CACHE=1Always re-downloads, bypassing cache

Cache Location ​

Downloaded files are saved to:

data/smartsheet/
├── loft-latest.xlsx
└── ann-latest.xlsx

Simulation Mode ​

If SMARTSHEET_API_KEY is not set, the system automatically runs in simulation mode:

bash
# Without API key - generates placeholder file
make pull BRAND=loft
# Output: ⚠️  Simulation mode: No API key found. Generating placeholder file.
1
2
3

What simulation mode does:

  • Generates a minimal Excel file with placeholder data
  • Uses the configured sheet ID from env var
  • Writes to data/smartsheet/{brand}-latest.xlsx
  • Allows testing the workflow without API access

When to use simulation mode:

  • Testing the workflow locally
  • Development without Smartsheet access
  • CI/CD pipelines where API key isn't available
  • Demonstrating the system to stakeholders

How It Works ​

1. Sheet ID Resolution ​

Sheet IDs are resolved from environment variables:

  • SMARTSHEET_SHEET_ID_LOFT for LOFT brand
  • SMARTSHEET_SHEET_ID_ANN for Ann Taylor brand

Error if the env var is not set for the active brand.

2. Cache Check ​

If a cached file exists and is within the TTL:

1. Check cache file exists → data/smartsheet/loft-latest.xlsx
2. Check file age < cacheTtlMinutes (default: 15)
3. If valid → Return cached path (skip API call)
4. If expired or --no-cache → Proceed to download
1
2
3
4

3. API Key Check ​

  • Present: Makes real API call to Smartsheet
  • Missing: Runs in simulation mode (generates placeholder)

4. Fetch Process ​

Real API Call:

1. Check API key → Found
2. Check sheet ID → Found (from env)
3. Make HTTPS request to api.smartsheet.com
4. Download sheet as Excel to data/smartsheet/{brand}-latest.xlsx
5. Return path for parsing

Simulation Mode:

1. Check API key → Missing
2. Check sheet ID → Found
3. Generate placeholder Excel in data/smartsheet/{brand}-latest.xlsx
4. Return path for parsing

Troubleshooting ​

Error: "Smartsheet sheet ID not configured" ​

Solution: Set the sheet ID in .env:

bash
SMARTSHEET_SHEET_ID_LOFT=your-sheet-id
1

Error: "Smartsheet API authentication failed" ​

Solution: Check your API key:

bash
echo $SMARTSHEET_API_KEY  # Should show your key
1

Simulation Mode When You Want Real Data ​

Solution: Set the API key:

bash
export SMARTSHEET_API_KEY=your-key
make pull BRAND=loft
1
2

Cache Showing Stale Data ​

Solution: Force a fresh download:

bash
make pull NO_CACHE=1
1

Or delete the cached file:

bash
rm data/smartsheet/loft-latest.xlsx
make pull
1
2

Best Practices ​

  1. Keep credentials in .env — never commit API keys or sheet IDs to git
  2. Use caching during development — 15-minute default avoids rate limits
  3. Use NO_CACHE=1 for critical updates — ensures latest data
  4. Use simulation mode for testing — no API access needed
  5. Set sheet IDs per brand — SMARTSHEET_SHEET_ID_LOFT, SMARTSHEET_SHEET_ID_ANN
