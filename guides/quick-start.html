Quick-Start Guide ​

First-time setup and minimal day-to-day workflow for LOFT and Ann Taylor. For the full step-by-step with expected output, see Producer Workflow. For how all producer guides fit together, see Producer guides overview.

Prerequisites ​

  1. Terminal open in the project directory
  2. Node.js 18+ — Check: node -v (should show v18.x.x or higher). Install from nodejs.org
  3. npm — Comes with Node.js. Check: npm -v
  4. Git — Required for multi-producer collaboration
  5. Excel file ready in docs/excel/ (or ask the developer to convert a raw Smartsheet export)

macOS / Linux only

This tool is built for Unix-based systems. Windows users should use WSL (Windows Subsystem for Linux).

Day 1 — First-Time Setup ​

Three commands. That's it.

bash
npm install
make setup
make pull
1
2
3

What happens:

  1. make setup — interactive wizard to pick your brand (LOFT or Ann Taylor) and data source
  2. make pull — syncs with Git, fetches data from Excel/Smartsheet, shows the status dashboard
  3. You pick a refresh from the interactive prompt (date/r#) — it becomes your sticky working selection

If you have a raw Excel from Smartsheet, ask the developer to convert it via the convert-excel.js script.

Which Command Do I Use? ​

Day-to-Day — Managing Live & Future Refreshes ​

1. Start your day ​

bash
make pull
1

This runs three steps:

  • Git pull — get your teammate's latest work
  • Fetch — parse the latest Excel/Smartsheet data
  • Dashboard — see all dates and their status (LIVE, READY, BUILD, NEW)

You'll be prompted to pick a working date. That selection sticks until you change it.

2. Build the selected date ​

bash
make build
1

Generates HTML templates and the OCAPI payload. If the date was already built or synced, the build guard tells you — no silent overwrites.

3. Review the preview ​

bash
make preview
1

Opens preview links in the output. Files are in dev-env/{brand}/refreshes/{date}/r#/preview/rendered/.

4. Push to SFCC staging ​

bash
make push
1

Automatically runs data quality checks (missing copy, duplicate IPIDs, unknown types) and payload validation before syncing. Errors block the push. Warnings show a y/n prompt.

Always preview first

Never push without reviewing the preview. The preview shows exactly what will appear on the site.

Staging only

make push syncs to staging, not production. Production deployment requires manual replication via make replicate.

5. Generate the changeout email ​

bash
make done
1

Verifies the date was synced, generates the email, and shows the git commit hint.

6. Save your work ​

bash
make commit
1

Stages and commits the date's refresh directory. Then git push when ready.

7. Switch to another date ​

bash
make select DATE=2026-02-16
make build
make push
1
2
3

Or just run make select with no arguments for the interactive picker.

Troubleshooting ​

IssueFix
"No refresh found"Run make pull first
"Already built" on make buildAlready generated — run make push or make edit to force
"Already synced" on make buildAnother producer synced this date — run make select for a different date
"Data quality check failed" on make pushFix data in Excel, re-fetch with make pull
"OCAPI not enabled"Run make setup and enable OCAPI, then make health
Wrong brandRun make switch TO=loft or make switch TO=ann
Need to fix a templateEdit HTML, then make edit
No date selectedRun make select or make pull

Tips ​

  1. Always run make pull first — this syncs your team's work and prevents conflicts
  2. Your date selection is sticky — no need to type DATE= on every command
  3. Build guards protect your team — you can't accidentally overwrite synced work
  4. make push validates automatically — no separate validation step needed
  5. Use make edit for hotfixes — it force-rebuilds, bypassing the build guard
  6. make status shows everything — replaces the old morning/today/upcoming/pending commands
