Quick Start ​

First-time setup and minimal day-to-day workflow for LOFT and Ann Taylor. Use Internal Onboarding as the canonical setup/access guide, then this page for a fast operator flow. For full approval details, see the Producer Guide.

Use Make Only ​

You do not need to run node directly. All producer commands are:

bash
make <command>
1

Run make help for the full list. If you need to use Node scripts, a developer should expose them via make.

Safe Rules ​

Read these first. They keep you safe.

  • Always verify before you push. Use make refresh and make reports OP=report DATE=... to check output.
  • Review changes before approving. When the tool shows what changed, read it before pressing Enter.
  • Only use YES=1 when you are confident. It skips the approval prompts.
  • Only use FORCE=1 when a developer tells you to. It overrides safety guards.
  • Replication is manual. You do the staging-to-production copy yourself in Business Manager.
  • make push only goes to staging. It does not touch the live site.
⚠️ Destructive / test-use-only commands (not for routine producer use)

These commands can delete data, overwrite many campaigns, or wipe local state. For testing or when explicitly directed; do not use in normal workflow.

CommandRisk
make fresh-installDestructive. Removes dev-env and node_modules, then reinstalls. All local state and built data are lost.
make delete DATE=...Destructive. Removes a refresh from SFCC and locally. Can remove live or synced content. Requires DATE=; use REFRESH=r1 if the date has multiple refreshes.
make push-all [YES=1]Loose cannon. Pushes every date for the brand to SFCC. With YES=1 there are no confirmation prompts. Use only for CI or when a developer directs.
make test-syncTesting only. Sync with auto-confirm (--yes --force). For CI/automation, not daily use.
make docs-deployPublishing. Deploys docs to GitHub Pages. Only the doc owner should run this.
make cleanRemoves all rendered preview files. Use only if a developer asks you to free space or reset previews.
make build-all [FORCE=1]Rebuilds every date for the brand. Batch/dev use; not for normal producer workflow.
make convert-excel INPUT=...Converts raw Excel; can overwrite files. Dev-only.

Flags to avoid unless a developer tells you: Do not use YES=1 (skips all approval prompts) or FORCE=1 (bypasses "already built" / "already synced" guards) unless a developer explicitly asks you to.

Prerequisites ​

For full access/ownership requirements, use Internal Onboarding. Quick checklist:

  1. Terminal open in the project directory
  2. Node.js 18+ — Check: node -v (should show v18.x.x or higher). Install from nodejs.org
  3. npm — Comes with Node.js. Check: npm -v
  4. Git — Required for multi-producer collaboration
  5. Excel file ready in data/excel/ (or ask the developer to convert a raw Smartsheet export)

macOS / Linux only

This tool is built for Unix-based systems. Windows users should use WSL (Windows Subsystem for Linux).

Day 1 — First-Time Setup ​

This section is intentionally short; onboarding details live in Internal Onboarding.

Single entry point: Run make status. If you have no configuration yet, it runs setup for you, then opens the status hub.

bash
npm install
make status
1
2

What happens:

  1. make status — if no config exists, the setup flow runs (view/edit configuration); after you save, status continues and may run pull when there are no refreshes
  2. You pick a refresh from the status hub (date/r#) — it becomes your sticky working selection

Alternative: You can still run make setup first to view or change configuration (brand, data source, OCAPI), then make pull to fetch and open the hub.

If you have a raw Excel from Smartsheet, ask the developer to convert it via make convert-excel INPUT=file.xlsx OUTPUT=output.xlsx.

From zero to preview (single path) ​

One deterministic path from clone to seeing a preview:

StepCommandExpected
1git clone <repo> then cd into projectProject directory
2npm installDependencies installed
3make statusIf no config: setup runs; then status hub (pull may run if no dates)
4Pick a refresh from the status hub (e.g. 2026-02-14/r1)Sticky selection set
5make refresh + make reports OP=report DATE=...Build output and inspect per-refresh zone/IPID detail

Preview files live under dev-env/{brand}/refreshes/{date}/r#/preview/rendered/.

Which Command Do I Use? ​

Day-to-Day ​

Daily loop: make status or make pull → pick refresh → make refresh → make push → make reports OP=report DATE=.... Use make status as your main entry point; it may run setup on first use if no config exists. For full step-by-step and expected output, see Producer Guide.

Always preview before push

make push syncs to staging only. Production replication remains manual in Business Manager.

Switching Brands ​

bash
make switch            # Toggle to the other brand (loft ↔ ann)
make switch BRAND=ann  # Or switch to a specific brand
make status            # Verify
1
2
3

Use make setup for full configuration (brand, source, OCAPI).

Troubleshooting ​

IssueFix
"No refresh found"Run make pull first
"Already built" / "Already synced"Run make push (if built) or make status to pick another refresh. Use "Force rebuild" in the status hub if needed.
Template editsmake status → pick refresh → "Force rebuild" action.
"Data quality check failed"Fix data in Excel, then make pull and retry.
Wrong brand / OCAPI issuesmake setup to reconfigure and verify OCAPI settings.

See Common Errors for more.
