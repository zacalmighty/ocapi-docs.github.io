Template Resolution ​

The system resolves templates in this order:

  1. Zone-specific: {assetType}/zones/{zone}.html
  2. Asset-type: {assetType}/template.html
  3. Default: _default.html

Example Resolution ​

For asset type HOMEPAGE with zone HP_HERO:

  1. Try: homepage/zones/hp_hero.html ✓ (if exists)
  2. Try: homepage/template.html
  3. Try: _default.html

Template Mapping ​

Asset types are mapped to template paths in src/config/templateMapping.js:

javascript
// Exact mappings
HOMEPAGE: "homepage/template"
PPH: "pph/template"
POPUP: "popup/template"

// Pattern matching (fallback)
/^PPH/i → "pph/template"     // All PPH variants
/BANNER/i → "banner/template" // All banner types

htmlSource Modes ​

Each asset type has an htmlSource configuration that controls how HTML is generated:

ModeWhen to UseTemplate Behavior
TEMPLATEAuto-generated contentAlways regenerates on LAUNCH/UPDATE
DEVELOPERHand-coded HTMLOnly regenerates on LAUNCH
HYBRIDTemplate with customizationPreserves edits

Configuration ​

Defined in src/config/slotsConfig.js:

javascript
HOMEPAGE: {
  updateBehavior: {
    htmlSource: "DEVELOPER",
    autoRegen: false,
    preserveHtmlOnUpdate: true
  }
}

Zone Composition ​

Multi-zone asset types (like HOMEPAGE) compose multiple zone templates into one OCAPI asset.

How It Works ​

  1. Each zone has its own template file in {assetType}/zones/
  2. Templates are saved individually to preview/templates/{assetType}/
  3. At sync time, ZoneComposer concatenates all zones
  4. One combined HTML asset is pushed to SFCC

Zone Order & Wrapper ​

Zone order is defined in src/config/slots.config.js. The composed output is wrapped in <div class="g3-hp"> with external resources prepended:

javascript
HOMEPAGE: {
  zones: [
    "HP_MOBILE_CATS", "HP_PROMO_NAV", "HP_TOP_BANNER",
    "HP_HERO", "HP_2T",
    "HP_CAT_IMAGE", 
    "HP_DUO", "HP_TRIO",
    "HP_FEATURED_SHOPS", "HP_SLOTS",
    "HP_BOTTOM_BANNER", "HP_RFLK_WIDGET", "HP_UGC_WIDGET",
    "HP_CHARITABLE_HUB_BAR", "HP_LEFT_NAV_CONTENT_SLOT"
  ],
  wrapperClass: "g3-hp",
  externalResources: {
    stylesheets: ["webassets/homepage/2024/updated-HP-v8.css", ...],
    scripts: ["webassets/homepage/2024/gsaptest.js", ...]
  }
}

Using a Variant ​

  1. Pick the variant file from heroes/, banners/, or promos/
  2. Copy its content into the active zone file (e.g., zones/hp_hero.html)
  3. Customize: Scene7 URLs, colors, hardcoded copy (eyebrow, H1, disclaimer)
  4. The engine fills in {{sfccUrl ...}} links and {{{copy}}} from Excel data
  5. Run make edit DATE=... to regenerate

Each variant file has detailed comments documenting its CSS classes, layout, alignment options, and what the developer needs to customize.

Auto-Detection in Zone Comments ​

The rendering engine automatically detects which hero template variant is active by scanning for the CSS class in the rendered HTML. The template name appears in the zone comment:

html
<!-- ZONE: HP_HERO | template: T5 (Knockout 3-Col) | action: LAUNCH | asset: loft-2026-01-26-r1-homepage-hp-hero -->
1

This helps ecom managers quickly identify the layout in use without inspecting the HTML.

Rendered File Header Comment ​

Each composed rendered file (e.g., rendered/homepage.html) starts with an asset identification comment:

html
<!-- asset: loft-2026-02-08-r1-homepage | type: HOMEPAGE | zones: 11 -->
1

For single-zone types like PPH:

html
<!-- asset: loft-2026-02-08-r1-pph | type: PPH | items: 3 -->
1

This makes it easy to identify the corresponding SFCC asset when previewing files.

The variant map is defined in src/config/slots.config.js under ZONE_TEMPLATE_VARIANTS and can be extended for other zones in the future.

Best Practices ​

  1. Keep templates fragment-only - No <html>, <head>, <body> tags
  2. Use semantic class names - .hero-tile not .div1
  3. Include data attributes - data-asset-id for debugging
  4. Add IPID tracking - data-ipid on all links
  5. Test with sample data - Use make preview before sync
  6. Document placeholders - Add comments for complex templates

Validation Errors ​

Common template errors to watch for during make build/make preview:

ErrorCauseFix
