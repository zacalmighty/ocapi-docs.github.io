Template Authoring Guide ​

How to create and customize Handlebars templates for SFCC content assets.

Template Location ​

templates/
├── _default.html              # Fallback template
├── homepage/
│   ├── template.html          # Main homepage master template
│   └── zones/                 # Zone partials (one per homepage zone)

Copy field safety

The copy field can contain HTML formatting (e.g. <br>, <sup>, <span>). All copy values are automatically sanitized before rendering — dangerous elements like <script>, <iframe>, and event handlers are stripped. Use {{{copy}}} (triple-stash) to render HTML copy, or {{{safeCopy copy}}} for explicit sanitization. See Handlebars Helpers for details.

Template Resolution ​

The system resolves templates in this order:

  1. Zone-specific: {assetType}/zones/{zone}.html
  2. Asset-type: {assetType}/template.html
  3. Default: _default.html

Example Resolution ​

For asset type HOMEPAGE with zone HP_HERO:

  1. Try: homepage/zones/hp_hero.html ✓ (if exists)
  2. Try: homepage/template.html
  3. Try: _default.html

Template Mapping ​

Asset types are mapped to template paths in src/config/slots.config.js via resolveTemplate(assetType):

javascript
// Exact mappings (from slots.config ASSET_TYPES)
HOMEPAGE: "homepage/template"
PPH: "pph/template"
POPUP: "popup/template"

// Pattern matching (TEMPLATE_PATTERNS fallback)
/^PPH/i → "pph/template"     // All PPH variants
/BANNER/i → "banner/template" // All banner types

htmlSource Modes ​

Each asset type has an htmlSource configuration that controls how HTML is generated:

ModeWhen to UseTemplate Behavior
TEMPLATEAuto-generated contentAlways regenerates on LAUNCH/UPDATE
DEVELOPERHand-coded HTMLOnly regenerates on LAUNCH
HYBRIDTemplate with customizationPreserves edits

Configuration ​

Defined in src/config/slots.config.js:

javascript
HOMEPAGE: {
  updateBehavior: {
    htmlSource: "DEVELOPER",
    autoRegen: false,
    preserveHtmlOnUpdate: true
  }
}

Zone Composition ​

Multi-zone asset types (like HOMEPAGE) compose multiple zone templates into one OCAPI asset.

How It Works ​

  1. Each zone has its own template file in {assetType}/zones/
  2. Templates are saved individually to preview/templates/{assetType}/
  3. At sync time, ZoneComposer concatenates all zones
  4. One combined HTML asset is pushed to SFCC

Zone Order & Wrapper ​

Zone order is defined in src/config/slots.config.js. The composed output is wrapped in <div class="g3-hp"> with external resources prepended:

javascript
HOMEPAGE: {
  zones: [
    "HP_MOBILE_CATS", "HP_PROMO_NAV", "HP_TOP_BANNER",
    "HP_HERO", "HP_2T",
    "HP_CAT_IMAGE",
    "HP_DUO", "HP_TRIO",
    "HP_FEATURED_SHOPS", "HP_SLOTS",
    "HP_BOTTOM_BANNER", "HP_RFLK_WIDGET", "HP_UGC_WIDGET",
    "HP_CHARITABLE_HUB_BAR", "HP_LEFT_NAV_CONTENT_SLOT"
  ],
  wrapperClass: "g3-hp",
  externalResources: {
    stylesheets: ["webassets/homepage/2024/updated-HP-v8.css", ...],
    scripts: ["webassets/homepage/2024/gsaptest.js", ...]
  }
}

Testing a template locally ​

  1. Have a refresh that uses that asset type — Run make pull and pick a date that includes the type (e.g. HOMEPAGE, PPH).
  2. Generate output — Run make build (or make build FORCE=1 to force rebuild).
  3. Where files go:
    • Per-zone HTML: dev-env/{brand}/refreshes/{date}/r#/preview/templates/{assetType}/*.html
    • Composed previews: dev-env/{brand}/refreshes/{date}/r#/preview/rendered/*.html
  4. Open previews — Run make preview to print links, or open the preview/rendered/ files directly.
bash
make build                    # or make build FORCE=1 to force
make preview                  # prints preview URLs

Homepage zones ​

Homepage layout is defined entirely in templates/homepage/zones/. Each zone partial (e.g. hp_hero.html, hp_top_banner.html) is the single source for that zone; edit the zone file to change layout, copy, or styling. The hero zone uses the T5 Knockout 3-col layout (g3-hero--ko-3). Customize Scene7 URLs, colors, eyebrow/H1/disclaimer, and alignment classes (e.g. g3-text-block--left|center|right) directly in zones/hp_hero.html. Run make build or make build DATE=... FORCE=1 to rebuild.

Conventions: Use data-way-finding="homepage:<slug>" on each zone’s section or primary link (e.g. homepage:charitable, homepage:leftnav). Do not use data-asset-type="HOMEPAGE" on zone markup. Zone order comes from slots.config.js (which delegates to asset.config.js → HOMEPAGE.zones); Excel rows map into zones via HOMEPAGE_ZONE_PATTERNS (see Slots & asset types).

Auto-Detection in Zone Comments ​

The rendering engine automatically detects which hero template variant is active by scanning for the CSS class in the rendered HTML. The template name appears in the zone comment:

html
<!-- ZONE: HP_HERO | template: T5 (Knockout 3-Col) | action: LAUNCH | asset: loft-2026-01-26-r1-homepage-hp-hero -->
1

This helps ecom managers quickly identify the layout in use without inspecting the HTML.

Rendered File Header Comment ​

Each composed rendered file (e.g., rendered/homepage.html) starts with an asset identification comment:

html
<!-- asset: loft-2026-02-08-r1-homepage | type: HOMEPAGE | zones: 11 -->
1

For single-zone types like PPH:

html
<!-- asset: loft-2026-02-08-r1-pph | type: PPH | items: 3 -->
1

This makes it easy to identify the corresponding SFCC asset when previewing files.

The variant map is defined in src/config/slots.config.js under ZONE_TEMPLATE_VARIANTS and can be extended for other zones in the future.

Best Practices ​

  1. Keep templates fragment-only - No <html>, <head>, <body> tags
  2. Use semantic class names - .hero-tile not .div1
  3. Include data attributes - data-asset-id for debugging
  4. Add IPID tracking - data-ipid on all links
  5. Test with sample data - Use make preview before sync
  6. Document placeholders - Add comments for complex templates

Validation Errors ​

Common template errors to watch for during make build/make preview:

ErrorCauseFix
FORBIDDEN_TAGFound <html>, <body>, etc.Remove page-level tags
UNMATCHED_BLOCKMissing closing blockClose all block helpers
UNKNOWN_HELPERTypo in helper nameCheck spelling
SYNTAX_ERRORInvalid HandlebarsCheck brackets/quotes

Adding a new asset type ​

  1. Slots config — In src/config/slots.config.js, add the asset type (and template, slot, zones if needed). See Slots & Asset Types.
  2. Template file — Add templates/{name}/template.html (or rely on _default.html for simple types).
  3. Multi-zone (optional) — If the type has zones, add partials under templates/{name}/zones/ and define zones in slots.config.
  4. Verify — Run make build for a date that includes the type (or add test data), then make preview. See Output Paths for where files are written.
