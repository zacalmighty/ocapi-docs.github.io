Common Errors ​

Reference for common error messages and how to resolve them.

CLI exit codes ​

When the CLI exits (e.g. via make), the process code indicates:

CodeMeaningWhen you see it
0SuccessCommand completed normally
1Validation errorInvalid/missing input, refresh validation failed
2Sync errorOCAPI/network/slot or asset sync failure
3Auth errorSFCC 401/403 or missing credentials

See Runbook — CLI exit codes and Release checklist.

Build Guard Messages ​

"Already synced" (build guard) ​

Message:

⚠  Already synced. Choose a different refresh or rebuild:
   make status          (pick a different refresh)
   make build FORCE=1   (force rebuild)
1
2
3

Cause: This refresh was already pushed to SFCC. The build guard prevents accidental overwrites.

Solution:

  • Normal: Run make status to pick a different refresh, or make status DATE=...
  • Re-push needed: Run make build FORCE=1 to force rebuild, then make push FORCE=1

"Already synced" (push guard) ​

Message:

  • SFCC already has this date; no changes to sync for 2026-02-10/r1.
1

Cause: This refresh was already synced to SFCC. Push exits without calling OCAPI so you don’t re-run sync unnecessarily; the intended next steps are make replicate, make email, and make commit. When re-pushing with FORCE=1, only changed items are synced; if nothing changed, the same message is shown and slot binding is skipped.

What to do:

  • Normal: Run make replicate, then make email, then make commit
  • Re-push needed (e.g. to force re-push): Run make push FORCE=1

"Already built" ​

Message:

✔  Already built.
   make push            (push as-is)
   make build FORCE=1   (rebuild)
1
2
3

Cause: The HTML and OCAPI payload already exist for this refresh. No need to regenerate.

Solution:

  • Ready to deploy: Run make push
  • Need to rebuild: Run make build FORCE=1 after template edits

"Data quality check failed" ​

Message:

❌ 3 error(s) — fix before sync:
   • Item 5 (HOMEPAGE/hp_top_banner): Missing copy on LAUNCH
   • Item 7 (HOMEPAGE/hp_hero): Missing destination ID

Fix in Excel, then: make pull → make build → make push
1
2
3
4
5

Cause: The wireframe data has issues that would cause problems on the live site.

Solution:

  1. Fix the data in the Excel/Smartsheet source
  2. Re-fetch with make pull
  3. Rebuild with make build
  4. Push again with make push

"This date hasn't been synced yet" ​

Message:

⚠  This date hasn't been synced yet.
   Run: make push
1
2

Cause: Running make email before make push. Note that make push auto-generates the email, so you typically don't need to run make email separately.

Solution: Run make push first (which auto-generates the email). Use make email only if you need to regenerate the email standalone.

Solution:

bash
make setup

"No date selected" ​

Error:

❌ No date selected. Run 'make status' to pick a refresh, or pass DATE=

Cause: No sticky date set and no DATE= provided.

Solution:

bash
make status                  # Pick from the dashboard (sets active)

make status DATE=2026-02-03  # Direct set

❌ Invalid brand: 'xyz'. Valid brands: loft, ann

make switch TO=loft

OCAPI Errors ​

"OCAPI not enabled" ​

Error:

❌ OCAPI is not enabled. Run 'make setup' to enable.
1

Cause: OCAPI toggle is off in configuration.

Solution:

bash
make setup     # Enable OCAPI in the wizard
make health    # Verify connection
1
2

"Missing environment variables" ​

Error:

❌ Missing required OCAPI environment variables:
   - SFCC_CLIENT_SECRET
1
2

Cause: Required environment variable not set.

Solution:

  1. Create/edit .env file:
bash
SFCC_CLIENT_SECRET=your-secret-here
1
  1. Verify:
bash
make health
1

"401 Unauthorized" ​

Error:

❌ OCAPI Error: 401 Unauthorized
   Endpoint: /campaigns/loft-2026-02-03-r1
1
2

Cause: Invalid or expired OAuth credentials.

Solution:

  1. Check credentials in .env:
bash
SFCC_CLIENT_ID=correct-id
SFCC_CLIENT_SECRET=correct-secret
1
2
  1. Verify with health check:
bash
make health
1
  1. If credentials recently rotated, update .env.

"404 Not Found" ​

Error:

❌ OCAPI Error: 404 Not Found
   Asset: loft-2026-02-03-r1-homepage-hp_top_banner
1
2

Cause: Trying to UPDATE an asset that doesn't exist in SFCC.

Solution:

  • Change action to LAUNCH in wireframe, or
  • Sync the asset first with LAUNCH action

"429 Rate Limited" ​

Error:

⚠️ Rate limited. Retrying in 5s...
1

Cause: Too many API requests.

Solution: Wait and retry (automatic). If persistent:

  • Reduce concurrent operations
  • Wait longer between batches

"Connection timeout" ​

Error:

❌ OCAPI Error: ETIMEDOUT
   Could not reach SFCC API
1
2

Cause: Network issue or VPN not connected.

Solution:

  1. Check VPN connection
  2. Verify SFCC_BASE_URL is correct
  3. Test network: curl $SFCC_BASE_URL

Validation Errors ​

"Forbidden tag" ​

Error:

✖ hp_top_banner.html:1 — Forbidden tag: <!DOCTYPE html>
1

Cause: Template contains HTML tags that SFCC doesn't allow in content assets.

Solution: Remove forbidden tags from template:

  • <!DOCTYPE html>
  • <html>, </html>
  • <head>, </head>
  • <body>, </body>
  • <meta>
  • <title>

Templates should contain only fragment HTML.

"Unclosed block" ​

Error:

✖ template.html:25 — Unclosed block: {​{#each items}}
1

Cause: Handlebars block not properly closed.

Solution: Add closing tag:

handlebars
{​{#each items}}
<div>{​{this.name}}</div>
{​{/each}}
<!-- Add this -->
1
2
3
4

"Unknown helper" ​

Error:

✖ template.html:10 — Unknown helper: 'customHelper'
1

Cause: Using a Handlebars helper that isn't registered.

Solution:

  1. Check for typo in helper name
  2. Use built-in helpers (see Template Authoring)
  3. Or register custom helper in rendering/engine.js

Parser Errors ​

"Cannot parse sheet" ​

Error:

❌ Cannot parse sheet 'Q1'. Unrecognized format.
1

Cause: Excel sheet doesn't match expected format.

Solution:

  1. Specify format explicitly:
bash
make excel ARGS="--mode=converted"
1
  1. Check sheet structure matches expected format (see Wireframe Format)

"Missing required column" ​

Error:

❌ Missing required column: 'Action'
1

Cause: Expected column not found in Excel.

Solution: Verify Excel has required columns:

  • Zone/Slot identifier
  • Action (LAUNCH, UPDATE, etc.)
  • Date (or date header)

"Invalid date format" ​

Error:

❌ Invalid date: 'Feb 3, 2026'. Expected YYYY-MM-DD.
1

Cause: Date not in ISO format.

Solution: Use YYYY-MM-DD format in wireframe:

  • ✅ 2026-02-03
  • ❌ Feb 3, 2026
  • ❌ 02/03/2026

Status and dev-env ​

Status shows BUILD/READY for refreshes I know are on SFCC ​

Cause: Status uses local sync state first (e.g. dev-env/{brand}/refreshes/{date}/r#/sync-config.json). If you’ve deleted or recreated dev-env, that state is gone.

What to do:

  • When OCAPI is enabled, make status also checks SFCC: if the campaign for a refresh exists on the site, it is shown as SYNCED (or LIVE if today). So after a dev-env wipe, status can still show correct SYNCED/LIVE if the CLI can reach SFCC.
  • If OCAPI is disabled or SFCC is unreachable, status is local-only. Use make status to pick a refresh / make push as usual; to get accurate labels again, push those refreshes again or re-enable OCAPI. See FAQ — Why does status show BUILD/READY?.

1

Cause: File system permissions issue.

Solution:

bash
# Fix permissions
chmod -R 755 dev-env/

# Or check if file is locked by another process
lsof +D dev-env/

1

Cause: Brand directory doesn't exist.

Solution:

bash
mkdir -p dev-env/loft/refreshes
1

Getting Help ​

If you encounter an error not listed here:

  1. Check the error message for hints
  2. Run with debug mode: DEBUG=1 make build
  3. Run make status to see the current state
  4. Run make health to check SFCC connectivity
  5. Search existing documentation
  6. Contact the development team
