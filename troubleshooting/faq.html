Frequently Asked Questions ​

General ​

What does this tool do? ​

Transforms Smartsheet or Excel wireframes into production-ready SFCC content:

  • Fetches data from Smartsheet or Excel
  • Generates HTML from templates
  • Syncs to SFCC via OCAPI
  • Manages asset versions

How much time does it save? ​

Typical refresh: 2-4 hours → 15 minutes (85% reduction)

Workflow ​

What's the difference between pull, refresh, and reports report? ​

CommandWhat It DoesInputOutput
make pullGit sync + fetch data + auto-buildSmartsheet/Excelrefresh.json + ocapi-payload
make refreshRebuild selected refresh outputrefresh.jsonUpdated payload + assets
make reports OP=report DATE=...Show per-refresh zone/IPID detailrefresh manifestsAudit-friendly report output

pull gets fresh data and auto-builds; refresh rebuilds specific refreshes; reports report gives per-refresh zone/IPID visibility.

Why did make refresh skip output? ​

If nothing changed since the last build/sync, guards may skip. Use make refresh FORCE=1 or the "Force rebuild" action in make status to regenerate.

Can I process multiple dates at once? ​

Producers work one date at a time via make status. This is by design — build guards prevent accidental overwrites across dates. To build every date in batch, use make build-all (after make pull).

How do I preview changes before syncing? ​

bash
make refresh
make reports OP=report DATE=YYYY-MM-DD
1
2

make refresh rebuilds output for the selected refresh; reports report gives zone/IPID detail for review.

What if I need to edit content after generating? ​

Edit files in dev-env/{brand}/refreshes/{date}/r#/:

  • HTML: preview/templates/{assetType}/*.html
  • JSON: assets/{assetId}.json

Then use the "Force rebuild" action in make status to regenerate. Uses your sticky date.

Will my custom HTML get overwritten? ​

No. Assets in DEVELOPER mode preserve custom HTML across fetches. Only TEMPLATE mode assets regenerate.

See Asset Modes.

What if another producer already built my date? ​

The build guard will tell you. Run make pull to get their latest work, then make status to see the full board and pick a different refresh (or make status DATE=...).

See Multi-Producer Guide.

SFCC Integration ​

How do I check if SFCC connection is working? ​

Use make setup and verify OCAPI config values.

Can I sync to production directly? ​

No. The workflow is:

  1. make push → Validates data quality + syncs to staging
  2. Replicate manually in SFCC Business Manager for production

This prevents accidental production pushes.

How do I delete content from SFCC? ​

Status and dev-env ​

Why does status show BUILD/READY for refreshes I've already pushed? ​

LIVE and SYNCED come from two places:

  1. Local state in dev-env: each refresh has a sync section in dev-env/{brand}/refreshes/{date}/r#/refresh.json. After a successful make push, that section is updated with synced: true.
  2. SFCC (when OCAPI is enabled): when you run make status, the CLI also checks SFCC for each refresh's campaign (e.g. loft-2026-02-12-r1). If the campaign exists on the site, that refresh is shown as SYNCED (or LIVE if it's today's date), even when local sync state is missing (e.g. after you deleted dev-env).

So status is tied to both local and SFCC: local sync state is used first; when OCAPI is enabled, any refresh whose campaign exists on SFCC is treated as SYNCED/LIVE. After a dev-env wipe, make status can still show accurate SYNCED/LIVE for pushed refreshes as long as OCAPI is configured and the CLI can reach SFCC.

If you don't use OCAPI or SFCC is unreachable: status falls back to local-only. Deleting dev-env then means you'll see BUILD/READY for everything until you re-push or re-enable SFCC.

Troubleshooting ​

"Asset not found" error ​

The asset doesn't exist in SFCC yet. Check:

  1. Was the action set to LAUNCH?
  2. Did the initial sync succeed?

"Campaign already exists" error ​

A campaign with the same ID already exists. Either:

  1. Use UPDATE action instead of LAUNCH
  2. Delete the existing campaign first

"Authentication failed" error ​

Run make setup and re-check your .env credentials.

"Rate limited" error ​

The API is throttling requests. The client retries automatically, but if it persists:

  1. Wait a few minutes
  2. Reduce batch size
  3. Check for other processes hitting the API

Template not found ​

bash
make check
1

Ensure the template file exists in templates/{assetType}/template.html.

Empty preview ​

Check if:

  1. refresh.json has content
  2. Template exists for the asset type
  3. No validation errors
bash
make check

Performance ​

How long does a sync take? ​

OperationTime
Fetch5-10 seconds
Generate2-5 seconds per refresh
Sync1-2 minutes (depends on asset count)
Replicate2-5 minutes

Can I speed up syncing? ​

The API client uses batch operations and rate limiting. Speed is mostly limited by SFCC API response times.

Registry ​

How do I see zone/IPID details now? ​

Use slim reports:

  • make reports OP=report DATE=YYYY-MM-DD — per-refresh launched zone/IPID detail.
  • make reports OP=history ARGS="--zone=ZONE_KEY" — zone-level timeline.
  • make reports OP=coverage — IPID coverage summary.
